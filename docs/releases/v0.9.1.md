# Open Model Gateway v0.9.1

A security and maintenance patch after [v0.9.0](v0.9.0.md). It refreshes the runtime, isolates image publication from untrusted build inputs, and fixes dashboard accessibility and navigation details. It does not add database migrations or new provider capabilities.

## Security

- Replace the deprecated Debian 12 distroless runtime with a digest-pinned, supported Debian 13 image. The previous runtime contained OpenSSL affected by **CVE-2026-84782**; the replacement contains `libssl3t64 3.5.7-1~deb13u3`. This applies to the gateway and development loadtest image (#377).
- Keep image builds and scans in read-only jobs. Registry-writing jobs accept only validated immutable OCI artifacts and trusted, checksum-verified tools; third-party actions cannot run with write tokens (#371, #372, #374).
- Preserve each architecture's complete OCI graph, SPDX SBOM and provenance. Validate archive bounds, digests and associations before credentials are available; assemble and sign the exact native creation digest, refusing tag disagreement rather than selecting a mutable alias (#372).
- Update the verified signing tool to Cosign 3.1.4. Keyless acceptance checks bind signatures to the expected workflow, issuer and image digest, including wrong-identity, wrong-issuer and wrong-digest refusals (#375).
- Pin PostgreSQL and HTTPS verifier fixtures to reviewed digests (#369, #373).

These checks establish the tested publication boundaries; they are not a claim of reproducible gateway builds, universal dependency safety or an independent external security assessment.

## Dashboard fixes

- Show a neutral notice for an unavailable workspace without rendering its page or exposing identifiers. Clear the notice through normal navigation, and do not replay it after a document reload (#359).
- Keep technical scheduled-report configuration guidance visible only to Platform Admins. Make narrow report tabs discoverable and deployment-preview details readable and keyboard-scrollable (#359).
- Align Holds and log-link accessible names with visible text, and refresh the affected Bitop tab, filter and command-palette controls through the supported upstream workflow (#363, #365).

## Maintenance and verification

- Deduplicate CI runs and shard Rust tests behind a fail-closed required gate, while keeping dedicated privilege/contention tests and database fixtures isolated (#360).
- Make report-scheduling tests deterministic without freezing production authorization, leases or delivery fencing (#361).
- Update reviewed browser dependencies and TypeScript 6 tooling; preserve the unsafe-source inventory with Syn 3.
- Add real HTTP/runtime-role key-issuance contention measurements, controlled lock-stall recovery coverage and secret-safe steering-test failure diagnostics (#278, #132, #370).

The original sustained-load stall and intermittent steering-test `503` remain unresolved. The new measurements and passing controlled cases do **not** establish their causes or certify cluster capacity, HA behavior or a durability policy. The broader #222 compatibility program and external security review #61 remain incomplete.

## Upgrade

From **v0.9.0**, replace the image and restart using the normal drain procedure. There are **no new migrations or runtime-grant changes**: the latest migration is **0067**, with **66 migration records**, as in v0.9.0. Do not reset or recreate an existing database.

The base operating system, libraries and **CA trust store change**. Validate your outbound TLS integrations against the candidate before deployment, particularly private or legacy certificate chains. UID/GID `10001:10001`, the no-shell runtime and read-only execution remain unchanged. Publication acceptance is separate from production activation and authenticated/provider acceptance.

From an older release, also follow the [v0.9.0 upgrade instructions](v0.9.0.md#upgrade), including backups, explicit migrations/grants and stopping older replicas before the specified DDL. This patch does not remove those requirements.

## Verify the release

Download the assets from the GitHub release, then run `sha256sum -c checksums.txt`. The digest file identifies the immutable image; verify it with the expected identity:

```sh
image=$(tr -d '\n' < open-model-gateway-v0.9.1.digest.txt)
cosign verify "$image" \
  --certificate-identity https://github.com/ncecere/open-model-gateway/.github/workflows/image.yml@refs/tags/v0.9.1 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Check both platform SBOM assets against the SPDX documents attached to that image. A successful checksum or readiness check alone is not signature, provenance or authenticated acceptance.
