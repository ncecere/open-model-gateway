# Open Model Gateway: unreleased

Notes for changes on `main` after [v0.10.1](v0.10.1.md). They become the next release's notes.

## Behaviour changes

- **Management text limits count characters, not bytes** (#405). Every management text limit now counts Unicode characters (code points), matching the API contract's `maxLength` and the web forms: names (120), descriptions (2000), emails (320), OIDC group-mapping issuers (2048) and group values (512), upstream model IDs (512), the SMTP username (256), time zones (64), log and cost-report filters (200), compare ids (148), the sign-in callback code (8192) and provider-cost reconciliation text (account IDs 200, evidence references 256, model names 512, dimensions and cursors 4096). Text that was refused for its byte length but fits in characters (for example a 61-character name of two-byte letters) is now accepted; nothing that was accepted before is refused. The management contract drops its `x-omg-max-bytes` annotations, so `maxLength` is exact, except the settings support/logo URLs, whose limit applies to the stored, percent-encoded form (#419). Sign-in (the asserted email, 320; group values, 1024), SCIM emails and `bootstrap` emails count characters as well, so every account and group mapping the management API accepts can sign in and match. The dashboard counts characters too. The cost-report raw query bound is 16,384 bytes so both filters fit at their limit in any script. Requires migration **0069** (the provider-cost reconciliation text CHECKs count characters; no data change): run the migration before starting the new version, or provider-cost writes of long multibyte text fail with 409.

## New features

- **Restore a deployment's configuration and apply at a reviewed revision** (#87). The route review dialog now applies through `POST /platform/deployments/{id}/configuration/apply`, which writes only at the previewed revision: if the route changed since the preview (including a change away and back), nothing is changed and you review it again (`409 revision_conflict`). The route's History tab offers **Restore this configuration** on every recorded change: a preview of re-applying that change's value, then a new change, authored by you and linked to its source (`restored_from`); history is never edited. Platform Admin, browser session only; admin tokens and the existing PATCH/DELETE routes are unchanged. Requires migration **0070**.
