# Open Model Gateway: unreleased

Notes for changes on `main` after [v0.15.1](v0.15.1.md). They become the next release's notes.

## Operations

- **The cause of `503 accounting_unavailable` is now recorded** (#389). Until now nothing in production said why accounting failed. Each failed accounting operation increments the new counter `gateway_accounting_failures_total{stage,cause}` and writes one `WARN` log line, `accounting unavailable`, with the same two fields. `stage` is one of `route_lookup`, `pool_acquire_and_begin`, `governance_storage`, `explicit_settlement`, `cancellation_settlement`. `cause` is one of `pool_timeout`, `pool_closed`, `lock_timeout` (SQLSTATE 55P03), `statement_timeout` (57014), `backend_terminated` (57P01), `deadlock` (40P01 after the re-runs were used up), `read_only_transaction` (25006), `too_many_connections` (53300), `other_database`, `io`, `tls`, `protocol`, `worker_crashed`, `other`, and, for the 3 s settlement deadline, what the settlement was waiting on when it elapsed: `deadline_in_queue`, `deadline_acquiring_connection` (a starved pool) or `deadline_in_database` (a lock or statement wait). Both labels are fixed lists (48 combinations can occur); an unrecognised SQLSTATE is counted as `other_database`, and no SQL, value, message or identifier is exported or logged. Nothing is recorded when accounting succeeds, and no series exists before the first failure. Background accounting (reconciliation of expired holds, batch and job accounting, realtime session accounting) and an operator's usage reconciliation (`503 Reconciliation unavailable`) are counted the same way, so the counter can be higher than the number of `accounting_unavailable` responses. Not covered: realtime accounting deadlines, database errors in the job runner itself, and internal consistency checks. The log line carries `request_id` only when the failure happens before the response headers are sent, so not for the settlement of a streamed or cancelled response. The counter is in the System class of the OTLP metrics export, so it is exported wherever that export is enabled. See [operations](../operations.md#accounting-failures). No migration, no OpenAPI change, no runtime-grant change.
