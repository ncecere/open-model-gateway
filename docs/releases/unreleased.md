# Open Model Gateway: unreleased

Notes for changes on `main` after [v0.17.0](v0.17.0.md). They become the next release's notes.

## Security and verification

- **Property tests for the parsers the hard pass verified by hand** (#593). The OpenRouter price mapper (`microusd`, `map`, `map_with_endpoints`), the Bedrock Converse request encoder and the OpenAI Responses, Anthropic Messages and Bedrock ConverseStream parsers now have permanent `proptest` properties in place of the throwaway differential tests of the hard pass, each in a `*_property_tests.rs` module next to its target with bounded case counts and no regression file written to the tree. They assert invariants, not old outputs: no panic for any input (valid, mutated by dropping, duplicating, swapping and truncating events, wrong types, huge or negative numbers, oversized strings and unknown fields, or arbitrary JSON); every error is the documented class (`InvalidUpstream` for streams; `InvalidRequest`, `Unsupported` or `InvalidField` for the encoder, each of 34 faults refused with its own class); a stream terminates at most once and never on truncation, with usage exactly as reported (absent stays unknown, never `0`) and the block, tool and byte limits refusing rather than truncating; an accepted request is carried whole; and every price is a canonical integer micro-USD amount equal to an independent decimal reference, rounded up and flagged when inexact, with no missing, malformed, negative, over-range or non-string rate ever mapped to a free price. They found three real defects, kept as ignored regression tests and left unfixed here: `map_with_endpoints` panics when a catalog entry's `top_provider` is a string, number, boolean or array and the chosen endpoint lists `max_completion_tokens`; a prompt-size tier priced for a meter whose base rate is unusable leaves the price draft without the explicit `unknown` base line (fail-closed downstream and flagged `needs_review`); and the OpenAI Responses `State` has no terminated flag, so a second terminal frame would re-emit `Finish`, `Usage` and `Done` (unreachable through `execute`, which returns at the first `Done`). No gateway behaviour changes.
- **Five AGENTS.md rules are now checks, and every rule has a row in `docs/verification.md`** (#591). A new table, "AGENTS.md rules and their checks", lists each rule in AGENTS.md's Invariants and Deployment lists with the check that enforces it, or "review only" with the reason, and AGENTS.md points to it. The new checks, each with planted-violation tests that fail first: no `f32`/`f64`, float literal or SQL float cast in money code (the governance, billing, pricing, rates, metering, cost, spend, budget, ledger and rollup files, and any item that names `micro`, `usd`, `cost`, `price`, `spend` or `budget`), with two reviewed exceptions listed by file and item; `serve` never reaches `migrate`, `grants apply`, `bootstrap-*` or `provision-user` (a call graph over the gateway, plus both Dockerfiles running exactly `serve` and the Helm chart's gateway containers, which run `["serve"]` and wait with `wait-for-database --schema`); no provider id, adapter type or provider module named in `inference/`, so providers are reached only through `ProviderAdapter` and `ProviderRegistry`; every value a `tracing` call, `#[instrument]` or `print!` can log in the request path (`inference/`, `providers/`, `protocols/`, `jobs/`, `http.rs`, `auth`) is pinned to a reviewed snapshot, with credential and body words refused and `#[instrument]` without `skip_all` refused; and browser requests stay same-origin and relative, with every absolute URL literal and every `VITE_*` name pinned (none exist) and none allowed to look like a secret. No gateway behaviour changes. The provider-switch check found real switches outside the engine, in admission and batch planning (Anthropic cache-control pricing in three places and `PRIORITY_PROFILES`, the profiles that accept vLLM's `priority` request field); they are listed in the allowlist and left for a follow-up.
