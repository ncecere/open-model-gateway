# Open Model Gateway: unreleased

Notes for changes on `main` after [v0.15.1](v0.15.1.md). They become the next release's notes.

## Operations

- **The cause of `503 accounting_unavailable` is now recorded** (#389). Until now nothing in production said why accounting failed. Each failed accounting operation increments the new counter `gateway_accounting_failures_total{stage,cause}` and writes one `WARN` log line, `accounting unavailable`, with the same two fields. `stage` is one of `route_lookup`, `pool_acquire_and_begin`, `governance_storage`, `explicit_settlement`, `cancellation_settlement`. `cause` is one of `pool_timeout`, `pool_closed`, `lock_timeout` (SQLSTATE 55P03), `statement_timeout` (57014), `backend_terminated` (57P01), `deadlock` (40P01 after the re-runs were used up), `read_only_transaction` (25006), `other_database`, `io`, `tls`, `protocol`, `worker_crashed`, `other`, and, for the 3 s settlement deadline, what the settlement was waiting on when it elapsed: `deadline_in_queue` (its in-process slot; also what settlements queued behind a starved pool or a slow database report), `deadline_acquiring_connection` (a pooled connection or `BEGIN`) or `deadline_in_database` (a lock or statement wait). `pool_timeout` also covers a new connection that could not be opened in time (connection refused, the server at its connection limit or still starting), because sqlx retries those refusals until the acquire timeout. Both labels are fixed lists (5 stages and 16 causes, so at most 80 label combinations); an unrecognised SQLSTATE is counted as `other_database`, and no SQL, value, message or identifier is exported or logged. Nothing is recorded when accounting succeeds, and no series exists before the first failure. Background accounting (reconciliation of expired holds, batch and job accounting, realtime session accounting) and an operator's usage reconciliation (`503 Reconciliation unavailable`) are counted the same way, so the counter can be higher than the number of `accounting_unavailable` responses. Not covered: realtime accounting deadlines, database errors in the job runner itself, and internal consistency checks. The log line carries `request_id` only when the failure happens before the response headers are sent, so not for the settlement of a streamed or cancelled response. The counter is in the System class of the OTLP metrics export, so it is exported wherever that export is enabled. See [operations](../operations.md#accounting-failures). No migration, no OpenAPI change, no runtime-grant change.

## Contributors

- **Route authorization is pinned by a snapshot** (#522). `apps/gateway/src/route_policy.snapshot` lists every `ROUTES` entry in table order (methods, template, `Access`, admin-token policy), and a test fails with a line diff when the table changes without it, so weakening a declaration (for example `PlatformWrite` to `PlatformRead`) no longer passes unnoticed. Update it with `OMG_REGENERATE_ROUTE_POLICY=1`; a change to it is an authorization change and needs a security review. See [management API](../management-api.md). No behaviour change.
- **Declare a route on one line** (#521, part of #499). `ROUTES` in `apps/gateway/src/route_policy.rs` is now a `routes! { ... }` table that rustfmt leaves alone: add a route as `"GET POST" "/api/v1/..." => PlatformWrite, SETTINGS_WRITE;` (methods, template, `Access`, token policy) next to the entries it belongs with, instead of a six-line `route!(...)` call. The table holds the same 284 routes in the same order, and `route_policy.rs` leaves `tests/structure-allowance.json`. No behaviour change.
- `apps/gateway/src/identity.rs` is split into `identity/config.rs`, `identity/oidc.rs`, `identity/login.rs` and `identity/session.rs` (#512, part of #499): code moved unchanged, every `identity::` path is the same, and `identity.rs` leaves `tests/structure-allowance.json`. `IdentityState`, the principal types, the router and its route registrations, `AuthError` and the pruning jobs stay in `identity.rs`. Log events from the moved code now carry the child module as their target (`open_model_gateway::identity::session` for `could not record session activity`).
- `apps/gateway/src/alerts.rs` is split into `alerts/evaluation.rs` (what each rule kind watches), `alerts/incidents.rs` (firing and resolving incidents), `alerts/key_expiry.rs` and `alerts/message.rs` (email text) (#515, part of #499): code moved unchanged, no behaviour change, every `alerts::` path in use is the same, and `alerts.rs` leaves `tests/structure-allowance.json`. The rule types, the evaluation tick and the background loop stay in `alerts.rs`. Two warnings now log under a child module's target: `alert budget evaluation truncated` (`open_model_gateway::alerts::evaluation`) and the key-expiry reminder cap (`open_model_gateway::alerts::key_expiry`).
- `apps/gateway/src/jobs/runner.rs` is split into `runner/lanes.rs` (dispatch lanes and planning), `runner/line.rs` (one line's execution), `runner/segments.rs` (encrypted result segments) and `runner/repository.rs` (`LineRepository`, the batch line admission adapter) (#518, part of #499): code moved unchanged, no behaviour change, every `jobs::runner::` path in use is the same, and `runner.rs` leaves `tests/structure-allowance.json`. `start`, `Runner` and its lease loop, dispatch and finalization stay in `runner.rs`. Four warnings now log under a child module's target: `batch line state not recorded` (`open_model_gateway::jobs::runner::line`), the two `batch segment not ...` warnings (`open_model_gateway::jobs::runner::segments`) and the ungated batch line admission refusal (`open_model_gateway::jobs::runner::repository`).
- `apps/gateway/src/metrics.rs` is split into `metrics/registry.rs` (the constructor that registers every family), `metrics/requests.rs` (HTTP requests and upstream attempts), `metrics/admission.rs` (admission, settlement, accounting and lock waits), `metrics/alerts.rs`, `metrics/jobs.rs` (file store and batches), `metrics/operations.rs` (export, refusals, configuration, leases, reports and background runs) and `metrics/collection.rs` (scrape-time gauges read from the database) (#517, part of #499): whole methods of `impl Metrics` moved unchanged, metric names, help text, labels, buckets and exposition order are the same, every `metrics::` path is the same, and `metrics.rs` leaves `tests/structure-allowance.json`. The `Metrics` struct, `METRICS`, `bounded`, rendering, the router and the listener stay in `metrics.rs`. The registration inventory test in `metrics_export_tests.rs` now reads `metrics.rs` and every file in `metrics/` at run time, so a family registered in any of them is inventoried.
- `apps/gateway/src/scim.rs` is split into `scim/users.rs`, `scim/groups.rs` and `scim/discovery.rs` (#505, part of #499): code moved unchanged, no behaviour change, and `scim.rs` leaves `tests/structure-allowance.json`. Route registration, authentication and the last-admin guard stay in `scim.rs`.
- **Gateway files and functions can no longer grow** (#500, first step of #499). `npm run test:structure` (new, run in CI) fails when a gateway source file passes 800 production lines, or when a file already over that grows; the files over the limit today are listed in `tests/structure-allowance.json`, and that list can only shrink. Clippy now checks `too_many_lines` and `cognitive_complexity` in the gateway's non-test build; the functions that offend today are marked `expect(..., reason = "#499")`, and the marker must be deleted when the function is fixed. No gateway behaviour changes. See [verification](../verification.md#structure-ratchet).
- **`governance.rs` is split into child modules** (#503, part of #499): `governance/pricing.rs`, `policy.rs`, `admission.rs`, `settlement.rs` and `reconcile.rs`. Code moved unchanged and every `governance::` path is the same; the lock prefix helpers and the admission transaction (`admit_unobserved`) stay in `governance.rs`, which leaves the allowance list.
- **The randomness source scan reads whole files** (#506). `entropy::tests::only_this_module_draws_randomness` keeps every use of the `rand`/`getrandom` family of names inside `entropy.rs`. It stopped reading a file at its first `#[cfg(test)]`: that cut 138 of the 231 files it read. It now reads every `.rs` file under `apps/gateway/src` as tokens, except a file that is both declared only under a test gate and named as a test (`tests.rs`, `*_tests.rs`, or under a `tests/` directory), and leaves out only test modules (`#[cfg(test)]` or `#[cfg(all(test, ...))]` on a `mod`, at the top of a file or directly inside another module; a module inside a macro or function body is read). String literals are read by value, so a name spelled with `\x` or `\u` escapes is found. The names now include `getrandom`, `fastrand`, `rand_core`, `ThreadRng`, tokio's `thread_rng_n`, `rand_chacha`, `rand_pcg`, `rand_xoshiro`, `rand_distr`, `nanorand` and `oorandom`. `routing.rs` is no longer skipped: it must name exactly `rand` and `StdRng` (its seeded, non-secret candidate order) and must not re-export them. The wider scan found nothing else outside `entropy.rs`. Limits: an API that draws without one of these names, such as `Uuid::new_v4()`, is outside this scan (#511), and the shared file inventory follows `mod` declarations only, not `include!` or `cfg_attr` paths (#510). No gateway behaviour changes.
- The supply-chain test now refuses Dockerfile constructs that could make it read a stage BuildKit does not build, and the two ways other than `RUN` to bring outside content into a stage past its checks of `FROM` lines, which are `ADD` and an external image in `COPY --from=` or a mount (#485). Refused: `<<` in any instruction (heredocs, also split across a `\` continuation, here-strings and shifts), parser-directive comments (`# escape=`, `# syntax=`) and `#!` lines, any instruction outside a fixed list (so `ADD`, `ONBUILD`, `MAINTAINER` and the `//syntax=` line that selects another build frontend), non-ASCII and control characters and CRLF, a `FROM` that spans lines or takes its image from an `ARG`, blank lines or comments inside a continued instruction, `COPY --from=` or a `RUN --mount=` `from=` that is anything but the name of an earlier stage (no stage index and no external image, pinned by digest or not), and `COPY`/`RUN` flags with characters outside a plain set (no variables, quotes, backslashes or globs). What a `RUN` command does is not checked: the builds still fetch from the network (`npm ci`, `cargo build`). Neither Dockerfile used any of the refused forms. Each failure names the file, the line and the rule; the rules are in [verification.md](../verification.md#supply-chain).
- **The local supply-chain tests need Bash 4.4 or newer first on `PATH`** (#380). `npm run test:supply-chain` and `tests/oci-tool.test.mjs` now fail immediately, naming the required and the found version, when `bash` is older, missing or not Bash; they are never skipped. Under macOS's `/bin/bash` 3.2 two refusal tests used to see guards return 0, because before Bash 4.1 a failing `[[ ]]` does not end a `set -e` script. Install a newer Bash (for example Homebrew's) and put it first on `PATH`. CI is unchanged (Bash 5.2). Details: [verification.md](../verification.md#bash-for-the-shell-fixtures).

## Dependencies and CI

- **`rustix` 1.1.6** (#491), for RUSTSEC-2026-0486 (the extended-attribute functions could mark unwritten bytes as initialized). `rustix` reaches the build only through `tempfile`, a test dependency, so it is not in the gateway binary; the update clears the advisory.
- **CI runs on an exact runner image** (#491). `ci.yml` used the floating label `ubuntu-latest`, which changes the operating system under a job without a commit; it now names `ubuntu-24.04` like every other workflow. The supply-chain test refuses a floating, self-hosted or computed runner and a reusable workflow from outside the checkout. See [verification](../verification.md#supply-chain).
- **CI no longer installs operating-system packages at run time** (#491). `age` for the backup tests is the pinned v1.3.2 release, downloaded through `fetch-verified.sh` with its SHA-256; Playwright installs its browser without `--with-deps`. `apt-get` against the Ubuntu mirrors was unpinned, and on 2026-11-11 the runners could not resolve the mirrors, which failed three jobs on every pull request. The supply-chain test refuses a package manager in any workflow `run:` step; it does not read scripts those steps call.
