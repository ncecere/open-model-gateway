# Open Model Gateway: unreleased

Notes for changes on `main` since v0.6.1. They become the next release's notes.

## Security

- **Every route has a declared, tested authorization** (#195). Prompted by LiteLLM CVE-2026-35029, where a route-prefix allowlist let any logged-in user reach a configuration API. Every method and route template the gateway serves is declared in `apps/gateway/src/route_policy.rs` with its required access, matched exactly (never by prefix). Management routes are checked against that declaration before the request body is read, and an undeclared management route is refused even for a Platform Admin; handlers keep their own checks. Tests compare the declarations with the routes found in the source, check every route against 15 kinds of caller, and pin the seven unauthenticated routes. Management requests now make one extra read before the handler (about 1 ms per workspace request and 2–3 ms per platform request in a local measurement; see [operations](../operations.md#read-snapshots-and-the-reporting-replica)).

  Refusals you may notice:
  - A workspace member who isn't an admin, rotating another person's API key, gets `404` in every state (it was `403` for an active key). Workspace admins still get `403`, and now also for a disabled key (it was `key_disabled`).
  - Auditors who aren't members of a workspace get `403` instead of `404` on its key-policy routes.
  - Platform-admin-only workspace actions refuse non-admins with `403` before looking up the workspace.
  - Malformed workspace or key ids in a management path return `404`.

- **No management API can set environment variables, file paths or code** (#197). Prompted by LiteLLM CVE-2026-35029, where a configuration API could set environment variables (leading to file reads and admin takeover) and load code. An inventory of every management and SCIM write found no such setting in Open Model Gateway; tests now pin that every JSON management body rejects unknown fields, that the logo is stored as an object (never a path), that unsafe code and process spawning stay in their reviewed places, and that CI checks a denylist of template, scripting and dynamic-loading crates. One real gap was fixed: a credential reference could resolve to one of the gateway's own secrets if an operator had put its name on an allowlist by mistake.

  **Upgrade:** the gateway now refuses to start if `GATEWAY_SECRET_ENV_ALLOWLIST` or `GATEWAY_SMTP_SECRET_ENV_ALLOWLIST` names one of its own secrets: `DATABASE_URL`, `GATEWAY_*`, `AWS_*`, the database client's `PG*` variables, the proxy variables (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`), `OTEL_*`, or a variable selected by a `GATEWAY_*_ENV` setting. The message names the setting and the entries, never values. Remove them, give providers and SMTP their own variables, and restart. `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` stay referenceable, with a startup warning that a custom-endpoint connection would receive them. See [credential allowlists](../operations.md#credential-allowlists).

- **No request input can choose an upstream destination or credential (#196).** An audit against the LiteLLM client-side-credentials class of bug (CVE-2026-59823) found none. The [threat model](../threat-model.md#provider-credentials-and-egress) now lists every outbound call and who controls its destination, and tests send steering bodies, headers and model strings through the inference protocols against an approved and an attacker mock upstream. It found and fixed three smaller gaps:
  - **Local-upstream approvals.** An `https://` approval could name a 6to4 or Teredo IPv6 address that embeds a metadata, link-local or loopback IPv4 address. Such an address is now judged by the IPv4 address it carries: an embedded metadata or link-local address is refused, and an embedded loopback address only with `GATEWAY_ENV=development`. A private or public embedded address is still accepted over HTTPS, as the plain address is, and everything else (NAT64 included) is decided as before. Refusing more special-use ranges needs a startup-compatible migration and is tracked in #203.
  - **Model names.** A `model` containing a NUL or other control character, or longer than a database index entry, returned `503 accounting_unavailable` (or reached a query it could never match). It is now `404 model_not_found` without a query. Every other name is still looked up exactly, so a model name added by SQL with a space, `@` or an accented letter keeps working.
  - **Provider job and file ids** of `.` or `..` were accepted as a URL path segment. They are refused.

- CI no longer runs third-party code next to a token that can write (#194). The release image pipeline (`image.yml`) is split: `build` pushes each architecture by digest using only `actions/checkout` and the `docker/*` build actions; a read-only `verify` job (`contents: read`, `packages: read`) pulls that digest and runs the version check, the staging rehearsal, the runtime contract test and the Trivy scan; `publish` tags and signs only after `verify` passes, with a pinned cosign binary instead of an installer action. The images, tags, signatures, SBOM and provenance attestations and Release assets are unchanged. CodeQL analysis (which downloads the CodeQL bundle) runs in a read-only job; only `upload-sarif` runs with `security-events: write`. Every job that can write first checks that the runner has its own Buildx, so `docker/setup-buildx-action` cannot download one.
- Every run-time download goes through `.github/scripts/fetch-verified.sh`, which checks a SHA-256 written in the workflow before the file is used: Trivy (v0.70.0, replacing `aquasecurity/trivy-action`), cosign (v3.0.6), helm (v3.18.4, replacing `azure/setup-helm`), kubeconform (v0.7.0) and Node.js (22.23.3, replacing `actions/setup-node`). cargo-deny is installed by `taiki-e/install-action`, which verifies its own manifest checksum.
- `npm run test:supply-chain` reads the workflows with the `yaml` package (strict, aliases resolved, local composite actions and reusable workflows followed) and fails when a job that can write, by explicit, inherited or default permissions, uses an action outside a short allowlist; when an action or `docker://` image is unpinned; and when a `run:` step downloads by any other means than the script. `yaml` 2.9.1 is a new dev dependency.

## Added

- **Separate inference base URL (#187).** Set `GATEWAY_INFERENCE_BASE_URL` (Helm: `gateway.inferenceBaseUrl`) to show the SDK base URL on key and model pages when inference uses a different host. Unset uses the dashboard origin plus `/v1`; dashboard API requests remain same-origin.
