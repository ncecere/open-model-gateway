# Open Model Gateway: unreleased

Notes for changes on `main` after [v0.17.0](v0.17.0.md). They become the next release's notes.

## Fixes

- **A gateway-run batch's runner can no longer write to a batch another runner has taken over** (#638). A runner holds a batch with a 60 s lease it renews every 15 s. If it stalled for the lease term (a frozen VM, a stopped process, starvation) or its renewals kept failing, another runner claimed the batch and marked the first runner's in-flight lines `interrupted`; the first runner then still wrote, because only a local flag, set later by its renewal task, told it. After such a stall you could see: the result of a billed line dropped, a segment-number collision that made the *new* owner lose every later result flush (its remaining billed lines reported `result_unavailable`), progress counters above the batch total for a while, the first runner finishing the batch and closing its budget envelope while the new owner still had lines running (the owner's later lines then failed to admit), and duplicate output files. Money stayed consistent and no line was sent to a provider twice. Now each claim bumps a **claim epoch** and every runner write checks `(runner id, epoch)` inside its own transaction while holding the batch's job row, so a takeover waits for a write in flight and a runner that lost the batch is refused at its next write: it admits and starts no further line, records no result, counter, segment or demand row, finishes nothing and closes no envelope (a result segment or output file it had already stored is deleted when its record is refused). Segment numbers are now taken by the database inside that transaction, so one lost or failed flush never makes later flushes collide; counters move in the same transaction as the line's state and only when that write moved the line out of `running`, so a line is counted once; a failed or refused lease renewal ends the run's work (a failing database ends it 45 s after the last successful renewal; a single failed renewal does not), and a process no longer re-claims a batch it is still running. **A line whose provider call completes after the takeover** is charged (its attempt settles at the real cost, so the batch's cost and the usage reports include it) but its result is not recorded: the new owner has already counted it failed and the batch's error file lists it as `result_unavailable`. This is the same outcome as a crashed runner's in-flight line; it is now consistent with the counters, not a silent drop. Migration `0081_batch_runner_epoch` adds `async_jobs.runner_epoch bigint NOT NULL DEFAULT 0` (a constant default: no table rewrite or scan, `ACCESS EXCLUSIVE` on `async_jobs` for an instant) and a `BEFORE UPDATE OF runner_epoch` trigger so epochs only move forward (`SHARE ROW EXCLUSIVE` on `async_jobs` until the migration commits, blocking writers, not readers, for milliseconds); there is no CHECK constraint or index to build. Run `grants apply` after `migrate` as usual: the runtime role gets `UPDATE(runner_epoch)`; `verify-privileges.sql` now expects the seventh `async_job%` trigger. **Rolling updates:** a release before this one does not know the epoch and can run beside the new one. The epoch column and trigger are harmless to it, and a batch it takes over still fences the newer runner that lost it (the fence also compares the runner id). The reverse is not fenced: a batch a newer runner takes over from an older runner that stalled can still be written by that older runner until it is replaced. Finish the update before relying on the fence; rolling back to v0.17.0 needs no schema change. New log lines: `batch runner no longer holds its batch; it stops working on it` (once per run) and `batch lease renewal failed`; failed renewals are counted at the existing `job_storage` stage, and no metric or label is added. Native (provider-run) batches, video jobs and the poller are not changed; their claim is a soft `next_poll_at` push and is tracked separately.
- **A malformed `top_provider` in the OpenRouter catalog no longer fails the price suggestion** (#634). When the public catalog returned a model whose `top_provider` was a string, number, boolean or array (not an object) and the chosen endpoint listed `max_completion_tokens`, the gateway panicked while building the suggestion, so a Platform Admin's request for `GET /api/v1/platform/deployments/{id}/price-suggestion` got no response: the connection was closed (a proxy in front may show a 502), the dashboard's price suggestion failed, and for an admin-token caller the audit trail kept an attempt that started and never completed. The process and other requests were not affected, and nothing stayed locked. The mapper now reads such a `top_provider` as absent, which is how it already treated every other malformed catalog field, and the chosen endpoint's own `max_completion_tokens` is the output ceiling; the draft is otherwise unchanged and no warning is added, because the ceiling comes from the endpoint, not from the malformed field. The price-tier copy from the catalog entry is likewise guarded against a non-object endpoint `pricing` (an endpoint without a readable prompt price was never chosen, so this was not reachable). The generated endpoint test now draws hostile `top_provider` values.

## Security and verification

- **Source comments no longer record review history, and a check keeps it that way** (#595). Comments such as "#98 PR 2 review item 5: ...", "found in the review of #37" or "(review rule 12)" go stale and give the next change a justification to copy instead of a rule to follow; git history and the PR record why. 125 such comments (comment blocks as the check reads them: 93 in `apps/gateway/src`, which show as 106 diff hunks because a few blocks changed in two places, and 32 in `apps/web/src`), plus three web comments that kept a bare review-rule number are restated as the invariant they carried, or dropped where the code already said it; no code changed. `cargo test -p open-model-gateway --all-features --lib source_rules::review_history` and `apps/web/src/lib/review-history.test.ts` (`npm run test:web`) now refuse such comments in production sources, reading real comments (not strings) from a Rust lexer and the TypeScript parser, from one shared pattern file with planted refused and allowed comments; product vocabulary (access-review reviewers, `needs_review`, "security review" as a requirement) passes without an allowlist. A `docs/verification.md` row and one sentence in AGENTS.md state the rule. `proc-macro2`'s `span-locations` feature is enabled for the crate's tests only.
- **Property tests for the parsers the hard pass verified by hand** (#593). The OpenRouter price mapper (`microusd`, `map`, `map_with_endpoints`), the Bedrock Converse request encoder and the OpenAI Responses, Anthropic Messages and Bedrock ConverseStream parsers now have permanent `proptest` properties in place of the throwaway differential tests of the hard pass, each in a `*_property_tests.rs` module next to its target with bounded case counts and no regression file written to the tree. They assert invariants, not old outputs: no panic for any input (valid, mutated by dropping, duplicating, swapping and truncating events, wrong types, huge or negative numbers, oversized strings and unknown fields, or arbitrary JSON); every error is the documented class (`InvalidUpstream` for streams; `InvalidRequest`, `Unsupported` or `InvalidField` for the encoder, each of 34 faults refused with its own class); a stream is never completed by truncation, a driver that stops at the first `Done` sees at most one terminal (by construction of the driver; the Anthropic parser also refuses every frame after `Done`), and usage is exactly as the terminal frames reported it, read independently (absent stays unknown, never `0`) unknown fields in guarded objects refused at any depth, deterministic sweeps of every single mutation of a rich stream, endpoint selection checked against an oracle, and the block, tool and byte limits refusing rather than truncating (a failing generated case must be pasted into a named regression test, as seeds are not persisted); an accepted request is carried whole; and every price is a canonical integer micro-USD amount equal to an independent decimal reference, rounded up and flagged when inexact, with no missing, malformed, negative, over-range or non-string rate ever mapped to a free price. They found three real defects. The first is fixed (see Fixes, #634): `map_with_endpoints` panicked when a catalog entry's `top_provider` was a string, number, boolean or array and the chosen endpoint listed `max_completion_tokens`. The other two are kept as ignored regression tests (#635, #636): a prompt-size tier priced for a meter whose base rate is unusable leaves the price draft without the explicit `unknown` base line (fail-closed downstream and flagged `needs_review`); and the OpenAI Responses `State` has no terminated flag, so a second terminal frame would re-emit `Finish`, `Usage` and `Done` (unreachable through `execute`, which returns at the first `Done`). No gateway behaviour changes.
- **An experimental TLA+ model of the money path** (#594). `spec/formal/` holds a small model of admission, settlement, cancellation, expired-lease reconciliation, operator evidence, failover, crashes, message loss and lease fencing, checked with TLC by `spec/formal/check.sh` (a pinned JRE image run with no network, and `tla2tools.jar` pinned by SHA-256). TLC found no violation of the reservation invariants in the model (the comparison with the code was by reading), deliberate bugs show that several independent guards together keep a settled reservation final, and the comparison found that the gateway-run batch runner's lease is not a fencing token (its writes carry no runner id; money stays safe, tracked in #638). It is documentation and a design-review aid, not a gate: nothing in CI or `package.json` runs it. No gateway code changed.

- **A maintained journey suite for Spark and local-demo environments** (#592). `scripts/journeys` replaces the ad hoc release-candidate scripts: `python3 -I scripts/journeys run --base http://127.0.0.1:3000 --label <tag> --summary .local/journeys/summary.json` (Python 3.12+) signs in as the five demo personas through the real OIDC redirect flow and runs 16 journeys (about 990 checks) against a forwarded environment: sign-in and sign-out, `/me`, workspaces of both shared kinds, keys including rotation, revocation and key policy, inference authentication and the documented `model_not_found` refusal for Chat Completions, Responses and Messages, members and invitations, platform administration and policy composition, model selection, catalogues and the live type defaults (written back unchanged only), the auditor's read-only boundary, access requests and reviews, report schedules, workspace alert rules and legal holds, reports and usage with their documented shape, health, the SPA fallback, CSRF and Origin refusals and the credential boundaries (an inference key or an admin token is not another family's credential, and a scope-gated route accepts a token only with the scope). Every journey has refusal cases, and every refusal check is harmless if the refusal regresses. Each journey creates its data under a unique `journeys-<run>-…` name and undoes it also when it fails (an undo that is refused is a failed check), so journeys run in any order and can be re-run, one run per environment at a time. The suite refuses a non-loopback base, a base with credentials, a gateway whose public origin differs from `--base`, and any gateway whose sign-in is not the passwordless demo issuer. The summary (mode 0600, no symlink) names the label, UTC time, run id, order and seed, and per journey the checks passed and failed with the expected and actual HTTP status and the duration, and never a response body, cookie, key, token or e-mail address, by construction (the recorder accepts only a name, statuses and a note from a fixed list, and check names must be literals). `docs/journeys.md` is the feature map, derived against the route table (`tests/journeys.test.py` fails when a route group of `route_policy.rs` has no row), with every flow that is not covered and why (no model server, provider or file store in the demo). `tests/journeys.test.py` runs in `npm run test:demo`. `docs/verification.md` has the release-candidate steps. No gateway code changed.

- **Five AGENTS.md rules are now checks, and every rule has a row in `docs/verification.md`** (#591). A new table, "AGENTS.md rules and their checks", lists each rule in AGENTS.md's Invariants and Deployment lists with the check that enforces it, or "review only" with the reason, and AGENTS.md points to it. The new checks, each with planted-violation tests that fail first: no `f32`/`f64`, float literal or SQL float cast in money code (the governance, billing, pricing, rates, metering, cost, spend, budget, ledger and rollup files, and any item that names `micro`, `usd`, `cost`, `price`, `spend` or `budget`), with two reviewed exceptions listed by file and item; `serve` never reaches `migrate`, `grants apply`, `bootstrap-*` or `provision-user` (a call graph over the gateway, plus both Dockerfiles running exactly `serve` and the Helm chart's gateway containers, which run `["serve"]` and wait with `wait-for-database --schema`); no provider id, adapter type or provider module named in `inference/`, so providers are reached only through `ProviderAdapter` and `ProviderRegistry`; every value a `tracing` call, `#[instrument]` or `print!` can log in the request path (`inference/`, `providers/`, `protocols/`, `jobs/`, `http.rs`, `auth`) is pinned to a reviewed snapshot, with credential and body words refused and `#[instrument]` without `skip_all` refused; and browser requests stay same-origin and relative, with every absolute URL literal and every `VITE_*` name pinned (none exist) and none allowed to look like a secret. No gateway behaviour changes. The provider-switch check found real switches outside the engine, in admission and batch planning (Anthropic cache-control pricing in three places and `PRIORITY_PROFILES`, the profiles that accept vLLM's `priority` request field); they are listed in the allowlist and left for a follow-up.
