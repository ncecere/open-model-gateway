# Open Model Gateway: unreleased

Notes for changes on `main` after [v0.17.0](v0.17.0.md). They become the next release's notes.

## Security and verification

- **A maintained journey suite for Spark and local-demo environments** (#592). `scripts/journeys` replaces the ad hoc release-candidate scripts: `python3 -I scripts/journeys run --base http://127.0.0.1:3000 --label <tag> --summary .local/journeys/summary.json` (Python 3.12+) signs in as the five demo personas through the real OIDC redirect flow and runs 16 journeys (about 990 checks) against a forwarded environment: sign-in and sign-out, `/me`, workspaces of both shared kinds, keys including rotation, revocation and key policy, inference authentication and the documented `model_not_found` refusal for Chat Completions, Responses and Messages, members and invitations, platform administration and policy composition, model selection, catalogues and the live type defaults (written back unchanged only), the auditor's read-only boundary, access requests and reviews, report schedules, workspace alert rules and legal holds, reports and usage with their documented shape, health, the SPA fallback, CSRF and Origin refusals and the credential boundaries (an inference key or an admin token is not another family's credential, and a scope-gated route accepts a token only with the scope). Every journey has refusal cases, and every refusal check is harmless if the refusal regresses. Each journey creates its data under a unique `journeys-<run>-…` name and undoes it also when it fails (an undo that is refused is a failed check), so journeys run in any order and can be re-run, one run per environment at a time. The suite refuses a non-loopback base, a base with credentials, a gateway whose public origin differs from `--base`, and any gateway whose sign-in is not the passwordless demo issuer. The summary (mode 0600, no symlink) names the label, UTC time, run id, order and seed, and per journey the checks passed and failed with the expected and actual HTTP status and the duration, and never a response body, cookie, key, token or e-mail address, by construction (the recorder accepts only a name, statuses and a note from a fixed list, and check names must be literals). `docs/journeys.md` is the feature map, derived against the route table (`tests/journeys.test.py` fails when a route group of `route_policy.rs` has no row), with every flow that is not covered and why (no model server, provider or file store in the demo). `tests/journeys.test.py` runs in `npm run test:demo`. `docs/verification.md` has the release-candidate steps. No gateway code changed.

- **Five AGENTS.md rules are now checks, and every rule has a row in `docs/verification.md`** (#591). A new table, "AGENTS.md rules and their checks", lists each rule in AGENTS.md's Invariants and Deployment lists with the check that enforces it, or "review only" with the reason, and AGENTS.md points to it. The new checks, each with planted-violation tests that fail first: no `f32`/`f64`, float literal or SQL float cast in money code (the governance, billing, pricing, rates, metering, cost, spend, budget, ledger and rollup files, and any item that names `micro`, `usd`, `cost`, `price`, `spend` or `budget`), with two reviewed exceptions listed by file and item; `serve` never reaches `migrate`, `grants apply`, `bootstrap-*` or `provision-user` (a call graph over the gateway, plus both Dockerfiles running exactly `serve` and the Helm chart's gateway containers, which run `["serve"]` and wait with `wait-for-database --schema`); no provider id, adapter type or provider module named in `inference/`, so providers are reached only through `ProviderAdapter` and `ProviderRegistry`; every value a `tracing` call, `#[instrument]` or `print!` can log in the request path (`inference/`, `providers/`, `protocols/`, `jobs/`, `http.rs`, `auth`) is pinned to a reviewed snapshot, with credential and body words refused and `#[instrument]` without `skip_all` refused; and browser requests stay same-origin and relative, with every absolute URL literal and every `VITE_*` name pinned (none exist) and none allowed to look like a secret. No gateway behaviour changes. The provider-switch check found real switches outside the engine, in admission and batch planning (Anthropic cache-control pricing in three places and `PRIORITY_PROFILES`, the profiles that accept vLLM's `priority` request field); they are listed in the allowlist and left for a follow-up.
