# Open Model Gateway: unreleased

Notes for changes on `main` after [v0.15.1](v0.15.1.md). They become the next release's notes.

## Operations

- **The cause of `503 accounting_unavailable` is now recorded** (#389). Until now nothing in production said why accounting failed. Each failed accounting operation increments the new counter `gateway_accounting_failures_total{stage,cause}` and writes one `WARN` log line, `accounting unavailable`, with the same two fields. `stage` is one of `pool_acquire_and_begin`, `governance_storage`, `explicit_settlement`, `cancellation_settlement`; `cause` is one of `pool_timeout`, `pool_closed`, `lock_timeout` (SQLSTATE 55P03), `statement_timeout` (57014), `backend_terminated` (57P01), `deadlock` (40P01 after the re-runs were used up), `other_database`, `io`, `tls`, `protocol`, `worker_crashed`, `other`, `deadline_exceeded` (the 3 s settlement deadline). Both labels are fixed lists (26 combinations can occur); an unrecognised SQLSTATE is counted as `other_database`, and no SQL, value, message or identifier is exported or logged. Background accounting work (reconciliation, batch and realtime bookkeeping) is counted the same way when it fails, so the counter can be higher than the number of 503 responses. Nothing is recorded when accounting succeeds, and no series exists before the first failure. The counter is in the System class of the OTLP metrics export, so it is exported wherever that export is enabled. Not attributed yet: `accounting_unavailable` from the route lookup before admission, from batch and video job bookkeeping, and from internal consistency checks. See [operations](../operations.md#metrics). No migration, no OpenAPI change, no runtime-grant change.
