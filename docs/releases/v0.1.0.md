# Open Model Gateway v0.1.0

v0.1.0 (tag `v0.1.0`, commit `092e4cb`, 2026-10-08) is the first release of the single-enterprise rebuild: one installation per enterprise, with Team, Project and private personal workspaces as the security boundary. It replaces the earlier multi-organization prototype, which has no upgrade path. The decisions behind it are in [enterprise rebuild](../enterprise-rebuild.md).

## Highlights

- **One enterprise, three workspace kinds.** Teams and Projects are sibling shared workspaces with owner, admin and member grants. Personal workspaces are owner-private: Platform Admins and Auditors see their usage and cost totals, never their keys or request details.
- **Platform roles from OIDC, not because of OIDC.** User, Auditor and Admin are explicit entitlements. Signed OIDC group claims map to roles at sign-in, kept separate from manual grants. Losing entitlement revokes sessions and keys after a 30-day grace period, and revoked keys never come back.
- **Catalogs and model access.** Several catalogs with live workspace-type defaults, per-workspace replacement overrides and direct assignments. A model removed from a key is not silently restored when it becomes eligible again.
- **Workloads and providers.** Chat Completions, Responses, Messages, embeddings, base64 image generation, audio transcription and speech, rerank and TypeSafe System One, on OpenAI, Anthropic, AWS Bedrock (default, named-profile and assume-role access, optional VPC endpoint), OpenRouter and approved local profiles (OpenAI-compatible, vLLM, SGLang, Ollama).
- **Accounting.** Immutable, cache-aware prices in integer micro-USD; a durable reservation per upstream attempt; request and token quotas, concurrency leases and budgets per UTC day, ISO week, month or lifetime at every policy layer, plus an optional installation-wide budget. Unknown usage is never counted as zero.
- **Dashboard.** A React SPA served by the Rust binary: Workspace (Home, Models, API keys, Logs, Usage & costs, Settings) and Admin (Users, Teams, Projects, SSO groups, Connections, Models and prices, Catalogs, limits, cost centers, Logs, Usage, audit, Settings).
- **Logs** with Requests, Generations and Sessions, per-attempt telemetry (finish reason, time to first token, reasoning tokens) and optional client session and app labels. Prompt and response bodies are not stored.
- **Admin Settings:** general, defaults and limits, data and privacy (OpenRouter data collection, log retention), SMTP email and read-only sign-in status.
- **Staging baseline:** a non-root container image, HTTPS ingress and separate bootstrap, migrator and runtime database roles with an explicit runtime grant allowlist (`deploy/staging/runtime-grants.sql`).

## Migrations

Enterprise migrations `0001` to `0010`, applied only by the explicit `migrate` command:

| Migration | Adds |
|---|---|
| `0001_enterprise` | The enterprise schema: installation, identities, workspaces, grants, catalogs, keys, prices, reservations, ledger, audit |
| `0002_multimodal_pricing` | v3 price lines for multimodal workloads |
| `0003_v3_token_ceilings` | Token ceilings on v3 prices |
| `0004_budget_period` | A period (day, week, month) per budget |
| `0005_stacked_budgets` | Stacked budgets and reversible key disablement |
| `0006_login_return_path` | Same-origin return path after sign-in |
| `0007_user_display_name` | Display name from the verified ID token |
| `0008_bedrock_auth` | Bedrock access modes and VPC endpoints |
| `0009_request_telemetry` | Per-attempt telemetry and client session labels |
| `0010_installation_settings` | Admin Settings (general, limits, privacy, email) |

## Configuration

All settings are environment variables; see `.env.example`. Notable ones: `DATABASE_URL`, `GATEWAY_LISTEN`, `GATEWAY_PUBLIC_URL`, `GATEWAY_WEB_DIR`, `GATEWAY_OIDC_ISSUER`, `GATEWAY_OIDC_CLIENT_ID`, `GATEWAY_OIDC_CLIENT_SECRET`, `GATEWAY_OIDC_GROUPS_CLAIM`, `GATEWAY_SECRET_ENV_ALLOWLIST`, `GATEWAY_LOCAL_UPSTREAMS`, `GATEWAY_AWS_PROFILE_ALLOWLIST`, `GATEWAY_BEDROCK_ENDPOINT_ALLOWLIST` and `GATEWAY_EXECUTION_DETAIL_RETENTION_DAYS`.

## Installing

New installations only. Do not run `migrate` against a database from the earlier multi-organization prototype: it is refused, and there is no upgrade path.

1. Create an empty PostgreSQL 17 database and run `open-model-gateway migrate` as the schema owner.
2. Apply `deploy/staging/runtime-grants.sql` for the runtime role (`python3 scripts/staging.py migrate` does both).
3. Provision the first Platform Admin with `open-model-gateway provision-user --email … --platform-admin`, then `serve`.

See [staging](../staging.md) and the [README](../../README.md).

## Known limitations

- Development software: not accepted for production. No live identity provider, production load or off-host recovery acceptance.
- Group changes are only seen at the next sign-in (no SCIM in this release).
- No metrics endpoint, alerts, async jobs (video, batches) or realtime audio.
- Native Responses and Messages streams buffer bounded content instead of sending token-by-token events.
- Live provider checks were small, capped manual requests. CI uses mock providers only.
- The binary reports `0.1.0`.
