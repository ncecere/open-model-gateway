# Open Model Gateway v0.7.1

Changes since [v0.7.0](v0.7.0.md): the merged compatibility fixes #215–219 only. This patch improves bounded SDK request/response behavior; it does not establish universal or drop-in SDK/provider compatibility or full protocol conformance.

## Upgrade and database compatibility

**No new migrations, runtime grants or environment settings relative to v0.7.0.** The enterprise schema still ends at **0048**. No application dependencies change in this release vehicle.

For an installation on v0.7.0, record the current image digest/configuration and keep a verified backup under the [operations runbook](../operations.md). Once this release is published and its exact image is accepted, deploy by verified digest, wait for `/health/ready`, and check sign-in, authorization denials and configured integrations. There is no new schema migration or grant application required by this patch; deployment automation may still verify schema and grants explicitly. Never reset or reinitialize an existing database.

**Upgrading from v0.6.1 also inherits all [v0.7.0 upgrade precautions](v0.7.0.md#before-you-upgrade)**, especially the [reserved credential allowlist refusal](v0.7.0.md#reserved-credential-names-now-stop-startup-197-pr-208), management denial-code changes and local-endpoint approval checks. Inspect names, not secret values; use separate dedicated provider/SMTP variables and do not bypass the refusal by copying gateway secrets. v0.7.0 also added no migrations or runtime grants relative to v0.6.1. For older installations, follow the intervening guides, including [v0.6.0's migrations 0038–0048 and settings/grants requirements](v0.6.0.md#upgrade-guide).

## Optional generation maxima (#215)

Priced Chat Completions and Responses requests may omit the generation maximum, including streaming requests. Each attempt uses the same admission-pinned price ceiling for its hold and upstream output cap; explicit maxima remain unchanged, never clamped. Native Anthropic Messages still requires `max_tokens`. Unpriced/unknown accounting behavior is unchanged.

Batch lines follow the same optionality. Initial admission rejects stale planning prices before accounting writes; admitted work retains its pinned price/cap while queued. The original uploaded file is unchanged. This is not an unlimited generation allowance or an implicit retry policy.

## Embedding encoding and validation (#216)

`/v1/embeddings` honors `float` and standard padded base64 of little-endian float32 vectors, including the ordinary OpenAI SDK base64 default. Raw HTTP omission/null remains float. Runtime vector/float validation and client response-size checks happen **before successful settlement**; failed responses retain valid token/cost evidence and unresolved holds.

Batch embedding lines remain float-only and explicitly reject base64. Other unsupported fields remain unsupported.

## Stateless Responses wire-output replay (#217)

Clients can reuse supported text/function-call `output` items from JSON or terminal streaming responses as followup `input`. Optional read-only item IDs/statuses and omitted/empty output-text annotations are validated without becoming state or authority; tool correlation still uses `call_id`. Function-call-output metadata retains its nullable semantics.

This is wire-output replay, not server-side conversation storage. Client-only parsed fields, nonempty annotations/citations, malformed metadata, stateful references and other unsupported content remain explicitly rejected. No caller-side maximum/store workaround is required for the supported subset.

## Permanent capability refusals and retries (#218)

`unsupported_capability` errors now carry `x-should-retry: false`, so ordinary OpenAI and Anthropic SDK clients do not repeat permanent refusals, including HTTP 501. Status codes and error bodies are unchanged. Transient errors retain client retry eligibility; each dispatched client retry requires its own durable admission, and unknown usage keeps its hold. Gateway upstream retry/failover policy is unchanged.

## Anthropic terminal fidelity (#219)

Valid native Messages `refusal` and `model_context_window_exceeded` no longer fail as invalid upstream responses. JSON/SSE preserve both stop reasons, including empty refusals, while accounting still requires valid usage evidence.

Cross-protocol mappings remain coarse: Chat maps these reasons to `content_filter`/`length`; text-only Responses maps them to incomplete `content_filter`/`max_output_tokens`, without typed refusal parts or relabeling streamed text. Logs retain their coarse labels. Interactive Anthropic Responses, typed refusal blocks and hosted-tool `pause_turn` remain unsupported. No implicit retry or caller maximum/store workaround is introduced.

## Verification, publication and remaining limits

Release-gate completion, independent release review, exact candidate-image acceptance and production acceptance are separate from merged scope. CI and the release PR record verification; these notes do not claim new live-provider, independent security or capacity certification. Mock/SDK contracts do not certify every SDK version or provider.

Images remain linux/amd64 and linux/arm64, with exact-digest staging/runtime-contract and vulnerability checks before tagging/signing, SBOM/provenance and cosign keyless verification. Release assets include per-platform SBOMs, the digest reference and checksums. Follow the [image publication instructions](../staging.md#image-ci-and-registry-publication) and [signature verification guide](v0.3.0.md#verifying-the-images), using `image.yml@refs/tags/v0.7.1` as the signing identity. A previously passing `main` build is not acceptance of this release candidate.

**Excluded and still remaining:** optional empty/successful function-tool fields (#220), consistent explicit nullable OpenAI defaults (#221), the API-help `max_tokens` alias correction (#225), and deterministic adapter refusal validation before durable admission (#228). The broader compatibility program #222 remains incomplete. This patch does not include #103, #46 or dependency update #211, and does not import unmerged branch work.

The [v0.7.0 limitations](v0.7.0.md#verification-and-known-limitations) continue: independent security review (#61), live SCIM acceptance (#60), steady-load stalls (#132), the second failover write outage (#149), unimplemented guardrails (#181) and IdP-initiated logout (#162); the Helm chart remains beta. There is no universal/drop-in SDK or provider claim, full-conformance claim, certified capacity number or production-ready claim.

Report security problems privately as [SECURITY.md](../../SECURITY.md) describes.
