# Open Model Gateway v0.14.1

A patch release after [v0.14.0](v0.14.0.md), and **the first published 0.14 release**. The `v0.14.0` tag was pushed, but its image workflow failed closed at the arm64 image scan. Two HIGH zlib vulnerabilities in the runtime base image stopped it before publication, so there is no v0.14.0 image, signature or GitHub release (#474). v0.14.1 is v0.14.0 with the runtime base image re-pinned to a patched digest. Everything in the [v0.14.0 notes](v0.14.0.md) applies to v0.14.1: access review campaigns (#90), migrations **0076**–**0079** and the runtime-grant changes.

These notes do not establish completed release qualification, authenticated/provider acceptance or authorization for production activation or v1.0.0.

## Fixes

- **Runtime base image** (#474). The runtime stage now uses `gcr.io/distroless/cc-debian13:nonroot@sha256:cc66d222f0a7ec996b78a99fe76a969bc80b539a5016ad866c14d1949bc6d0ab` (amd64 `sha256:436f1724…`, arm64 `sha256:ac81bd56…`) instead of `sha256:3ee00291…`. Its zlib is `1:1.3.dfsg+really1.3.1-1+deb13u1`, which fixes CVE-2026-85091 (heap buffer overflow in `gz_vacate()`) and CVE-2026-76844. Both are rated HIGH.
  - The only other package change in the base is `tzdata` and `tzdata-legacy` 2026e → 2026f.
  - The load-test image (`deploy/loadtest/Dockerfile`) uses the same runtime pin, and the supply-chain test approves only the new digest.
  - The build stages (Node and Rust images) are unchanged.

## Behaviour changes to note

- None beyond those in the [v0.14.0 notes](v0.14.0.md#behaviour-changes). This release changes no code, API, contract, schema or runtime grant. The binary and the SPA are built from the same source as the `v0.14.0` tag. The only differences are the runtime base-image pin, the version numbers, the supply-chain test's approved digest and the documentation.

## Contracts and documentation

- Both OpenAPI documents report `info.version` 0.14.1; nothing else changed.
- The v0.14.0 notes and the CHANGELOG say that v0.14.0 was not published and point here.

## Tests and CI

- The image workflow's scan did its job: Trivy 0.70.0 (`--severity HIGH,CRITICAL --ignore-unfixed`) refused the v0.14.0 image, and `publish` and `release` did not run. Locally, the same scan finds both CVEs in the old base digest and passes on the new one, for amd64 and arm64 (base images); a locally built v0.14.1 gateway image passes it too, and the tag run scans the published image.

## Dependencies

- Runtime base image only, as above. No Rust, npm or GitHub Actions dependency changed.

## Known limitations

- As in [v0.14.0](v0.14.0.md#known-limitations).
- The open Dependabot image update #458 (an older distroless digest plus build-image updates) is superseded for the runtime stage and will be handled in the dependency round.

## Upgrade

- **From v0.13.0:** follow the [v0.14.0 upgrade instructions](v0.14.0.md#upgrade), deploying v0.14.1 wherever they say v0.14.0. The steps include backup, drain, migrations **0076**–**0079** and `grants apply`.
  - The latest migration is **0079**, with **78 migration records**.
  - Rollback is as described there: redeploying v0.13.0 is safe only if no migration ran.
- **From a self-built v0.14.0:** replace the image. The schema and runtime grants are unchanged, so there is no migration and no `grants apply`, and a v0.14.0 replica serves the same database. The latest migration remains **0079**. Do not reset or recreate an existing database, run a down migration or bootstrap implicitly.

From an older release, also follow the [v0.13.0 upgrade instructions](v0.13.0.md#upgrade) and their linked requirements. Publication verification and readiness remain separate from production activation and authenticated/provider acceptance.
