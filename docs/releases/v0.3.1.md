# Open Model Gateway v0.3.1

v0.3.1 moves the runtime image to distroless (no shell), adds supply-chain scanning, adds rerank and System One for self-hosted servers, and fixes problems found during live DGX Spark acceptance and while capturing the v0.3.0 screenshots. It has no migrations. Generic OIDC sign-in was also accepted end to end against a self-hosted Authentik (no product changes were needed).

## Highlights

- **Distroless runtime image.** The runtime stage is `gcr.io/distroless/cc-debian12` (`:nonroot` variant, pinned by digest) instead of `debian:bookworm-slim`. There is no shell, package manager, curl or perl. The image still runs as UID/GID `10001:10001`, has the SPA in `/app/web` and works with a read-only root filesystem. Measured on linux/arm64: 226 MB → 104 MB unpacked (52 MB → 25 MB compressed). Trivy finds no fixable HIGH or CRITICAL issues in either image. Counting unfixed findings too, OS-package findings drop from 327 (1 CRITICAL, 63 HIGH) to 49 (0 CRITICAL, 1 HIGH). The Rust binary is not scanned as a Cargo artifact, before or after.
- **The binary is the entrypoint.** `ENTRYPOINT ["/usr/local/bin/open-model-gateway"]`, `CMD ["serve"]`. `deploy/container-entrypoint.sh` is gone. Its behaviour moved into the binary's startup, for every subcommand except `healthcheck` and before `.env` files or configuration are read: umask `077`; `_FILE` import for exactly `DATABASE_URL`, `GATEWAY_OIDC_CLIENT_SECRET`, `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` (readable regular file, one terminal LF removed, `_FILE` variable removed); refusal when a variable and its `_FILE` companion are both set, or a value is empty, over 4096 bytes, or contains CR, LF or NUL, with messages that never contain values or paths; no implicit migration or bootstrap. See [container image](../operations.md#container-image).
- **`open-model-gateway healthcheck`** `[--url http://127.0.0.1:8080/health/ready] [--timeout 3s] [--allow-non-loopback]`: exits 0 for a `2xx` from `/health/ready`, 1 otherwise. It defaults to the port of `GATEWAY_LISTEN` over loopback, accepts `http://` only, ignores proxy variables, never follows redirects and reads no configuration or secrets. The image `HEALTHCHECK` uses it in exec form ([health checks](../operations.md#open-model-gateway-healthcheck)).
- **Rerank and System One on self-hosted servers.** `/v1/rerank` routes can use `openai_compatible` (Jina/Cohere wire), `vllm` (its `/rerank`) and `sglang` (native shape: the gateway applies `top_n` itself so every pair's input tokens are observed). `/v1/systemone` routes can use `openai_compatible` (TypeSafe-compatible servers such as OpenJev) and `ollama` (v0.35.0+; `prompt_eval_cached_count` is recorded as cache reads). Ollama has no rerank API, and vLLM/SGLang no System One route, so those stay `unsupported_capability`. Add model offers these types only on profiles that serve them. Checked live against a DGX Spark Jina reranker and OpenJev System One ([details](../provider-adapters.md#local-rerank-and-system-one)).
- **Supply-chain scanning.** `cargo-deny` (`deny.toml`: RustSec advisories, licences, bans and sources; two documented advisory ignores with reasons), an npm production-dependency audit gate (`--omit=dev --audit-level=high`), CodeQL for JavaScript/TypeScript and Rust, and weekly grouped Dependabot updates for Cargo, npm, GitHub Actions and Docker base images. The Bedrock SDK no longer pulls in its legacy hyper 0.14/rustls 0.21 connector, which carried three advisories ([verification](../verification.md), [security policy](../../SECURITY.md)).
- **Tests and CI.** `npm run test:container` now builds the image (or uses `OMG_CONTAINER_IMAGE`) and checks the runtime contract against a throwaway PostgreSQL: no shell or tools in the filesystem, UID 10001, read-only root filesystem, `_FILE` secrets, `serve` refusing an unmigrated database without migrating, explicit `migrate`, a healthy `HEALTHCHECK`, and graceful `SIGTERM` as PID 1. It runs in CI's `staging-image` job and on each pushed digest in `image.yml`. The former shell-entrypoint cases are Rust tests (`startup.rs`, `tests/startup.rs`). `staging.py verify` checks the image with exec-form commands and `docker inspect` instead of `sh`/`curl` inside the container.

## Breaking and behaviour changes

- **No shell in the image.** Anything that ran `sh`, `curl`, `cat` or other tools inside the gateway container fails. Replace health checks with `["CMD", "/usr/local/bin/open-model-gateway", "healthcheck"]` (or Kubernetes `httpGet` probes) and debug with `docker exec CONTAINER /usr/local/bin/open-model-gateway healthcheck`, `docker logs`, `docker inspect`, or an ephemeral debug container.
- **Overriding `--entrypoint container-entrypoint`** no longer works; drop the override. Arguments after the image name are passed to the binary as before (`migrate`, `provision-user …`, `--version`).
- **Secret validation also applies outside containers.** The binary performs the `_FILE` import and validation itself, so a local run with, for example, `OPENAI_API_KEY=""` exported in the shell now stops with `secret configuration: OPENAI_API_KEY: secret must not be empty`. Values loaded from a `.env` file are not affected (they are read after the import, as before).
- `HOME` is `/nonexistent` in the image (as before, via the old passwd entry); distroless has no passwd entry for UID 10001, which nothing in the gateway needs.

## Fixes (found in live DGX Spark acceptance, 2026-10-09)

- **Reasoning models on local servers.** SGLang (and vLLM/Ollama with a reasoning parser) add `reasoning_content`/`reasoning` to the message or delta and `matched_stop`/`stop_reason` to the choice. Every local Chat response from such a server failed as `invalid_upstream_response`. Local profiles now accept those fields with scalar shapes only; the trace is not returned to clients (as on OpenRouter) and its tokens stay in `completion_tokens`. SGLang's top-level `usage.reasoning_tokens` is recorded as Logs telemetry. Cloud OpenAI decoding is unchanged.
- **Total-only input settles under pricing v3.** Servers that report only inclusive `prompt_tokens` (no cache split, as SGLang and default vLLM do) left uncached input unknown, so every priced local Chat attempt kept its hold as `unknown`. When every cache meter with an unknown count is `not_applicable`, uncached input is now the total minus the known cache parts ([cache pricing](../cache-pricing.md#pricing-v3-price-lines-and-meters)). Attempts settled `unknown` before this change keep their holds.

## Fixes (found while capturing the v0.3.0 screenshots, 2026-10-09)

- **Cooling-down routes are retryable, not missing.** When every route of an available model is in its circuit-breaker cooldown, every protocol now answers HTTP 503 `model_temporarily_unavailable` (OpenAI type `server_error`, Anthropic `overloaded_error`) with `Retry-After` set to the soonest reopening, instead of 404 `model_not_found`. Gateway-run batch lines wait for the cooldown instead of failing ([routing](../routing.md)).
- **Batch waits name the binding limit.** With the defaults (route batch limit 2 = per-batch cap 2) a full route read "Gateway batch workers busy"; it now reads "At its batch limit". A batch whose failed line has an unknown cost shows "At least $X" with the count in the tooltip instead of "Unknown"; settlement is unchanged (a failed attempt on a priced route still keeps an unknown cost). `cost_unknown_attempts` is added to batch rows.
- **Money reads simply.** Tiles, cards, table cells and chart labels round to cents from $0.01 up ("$8.27"; exact "$8.271628" in the tooltip) and keep two significant digits below a cent ("$0.0081", never "$0.00"). Prices, configured limits, inputs, the accounting breakdown and CSV exports stay exact.
- **Stat tiles line up.** Sparklines are pinned to the bottom of every tile at a fixed size, so tiles in a row draw their charts at the same height whatever the number of hint lines.
- **Unpriced unit-priced models say "Unpriced".** An image/audio model with no published price read "Priced per image"; Admin › Models and the workspace catalog now say "Unpriced". The workspace catalog adds `priced_routes`.
- **Audit log labels.** Alert-rule, file, batch, batch-scheduling, settings and SCIM last-admin events have short labels (codes stay in the tooltip); a test checks every code the gateway emits has one.
- **Users.** A denied sign-in that never had a platform role shows "No access" (not "Suspended") and keeps the token's display name.
- **Usage › By workspace** names personal workspaces `Personal · <owner>` instead of many identical "Personal" rows (platform totals only, as before).
- **Logs** fit at 1440 with capture-like data: tokens stack in/out, names truncate earlier, Attempts is optional (fallbacks show under Status) and Admin hides Finish by default (under Columns). `?model=` deep links are covered by a browser test.
- **Sizes** use one formatter: Settings › Storage now shows binary MB like Files and quotas (a 118 MB file read 124 MB there); hover shows exact bytes. Sizes are plaintext ([file storage](../file-storage.md)).
- **Limits.** A saved workspace budget no longer shows a disabled ×; it can only be lowered (tighten-only), which the row explains.
- **Key safety.** "Holder left" is documented as a defensive finding: every membership-ending path revokes the holder's keys, so it flags only keys changed outside those paths.

## Upgrading

No migrations and no new runtime grants (the new report and catalog queries read tables the runtime role can already select). API additions: batch rows `cost_unknown_attempts`, workspace catalog `priced_routes`; 503 `model_temporarily_unavailable` with `Retry-After` replaces 404 for models whose routes are all cooling down. Pull the new image by digest, replace any shell- or curl-based health checks and `--entrypoint` overrides, then deploy as usual.
