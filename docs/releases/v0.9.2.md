# Open Model Gateway v0.9.2

A maintenance patch after [v0.9.1](v0.9.1.md), covering operator privilege-probe fixture isolation and test-only native accounting diagnostics. It adds no dependencies, runtime features, provider capabilities or new CVE fixes.

Release qualification is tracked in #385. These notes do not establish completed qualification, authenticated/provider acceptance or authorization for production activation or v1.0.0.

## Fixed

- `grants verify` uses its own closed synthetic history for global alert fixtures. This prevents synthetic positive-history collisions when legitimate personal aged-hold or last-Admin SCIM incidents are open (#382, PR #383). The operator privilege probe does not mutate legitimate incidents or unknown holds, waive runtime grants or weaken refusal checks.

## Verification

- Security-matrix failure diagnostics capture bounded, request-owned native database outcomes and SQLSTATEs across detached accounting tasks, without SQL text, error messages, identifiers or credentials (PR #384). This instrumentation is test-only; production deadlines and cancellation behavior are unchanged.

The diagnostic addition does **not** establish the historical `accounting_unavailable` cause in #370; it remains unresolved. The original sustained-load stall also remains unresolved. Passing controlled tests do not certify cluster capacity, HA behavior or a durability policy. The broader #222 compatibility program and independent external security review #61 remain incomplete.

## Upgrade

From **v0.9.1**, replace the image and restart using the normal drain procedure only after qualification and deployment approval. The schema is unchanged: the latest migration remains **0067**, with **66 migration records**. There are **no new migrations or runtime-grant changes**. Do not reset or recreate an existing database, run a down migration or bootstrap implicitly.

From an older release, also follow the [v0.9.1 upgrade instructions](v0.9.1.md#upgrade) and their linked v0.9.0 requirements, including backups, explicit migrations/grants, replica ordering and outbound TLS validation. This patch does not remove those requirements. Publication verification and readiness are separate from production activation and authenticated/provider acceptance.
