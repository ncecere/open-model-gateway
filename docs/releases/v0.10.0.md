# Open Model Gateway v0.10.0

A minor release after [v0.9.3](v0.9.3.md). It publishes drift-checked OpenAPI 3.1 contracts for the whole management API and the supported inference API, and turns client input that used to surface as a 5xx or an undocumented 409 into a clear 400 (or a recorded result).

These notes do not establish completed release qualification, authenticated/provider acceptance or authorization for production activation or v1.0.0.

## API contracts (#38, #81, #82)

- **Management API** (`docs/openapi/management.openapi.json`, #81): every management route (251 operations), generated from the compiled route policy and reviewed schema sources, and checked against the real handlers: every documented response is validated against real captures, request boundary vectors are sent over HTTP to a running gateway on PostgreSQL, and coverage gates fail on any undocumented status, unreached request location or placeholder. Delivered in six slices: identity and self-service (#399), identity and access (#433), model setup (#436), money (#440), settings and alerts (#426), activity and credentials (#418).
- **Inference API** (`docs/openapi/inference.openapi.json`, #82): the supported inference subset (27 operations): models, embeddings, rerank, System One, images, Chat Completions, Responses and Messages (JSON and SSE, tools, usage, refusals), audio transcription and speech, files, batches, legacy videos and the realtime WebSocket upgrade. Stream grammars are checked by an SSE sequence validator, cancellation is backed by named HTTP drop tests, and the official `openai` and `@anthropic-ai/sdk` clients are replayed against the documented examples with no network or paid calls. Error envelopes are per protocol family and never the management envelope.
- **Integer encoding** (#431): request integers must be JSON integer literals, without a fraction, exponent or `-0`. JSON Schema cannot express this (spec-following validators accept `1.0`), so both documents declare `x-omg-integer-encoding: "json-integer-literal"` and the HTTP vectors pin the server's refusal at every integer request location. Pagination `offset` accepts a bare `-0` as zero.
- Rules JSON Schema cannot state are described in each operation and pinned by probes; the `x-omg-*` extensions are listed in `docs/openapi/management/README.md` and `docs/openapi/inference/README.md` (SDK generation does not cover them). Site publication of the documents remains separately authorized.

## Fixes

- **Control characters reaching PostgreSQL** now return 400 instead of 5xx: list `q` and the file `search` (#404, #415); OIDC group-mapping issuers, which also refuse whitespace (#427, #429); model and catalog descriptions, which keep tab, LF and CR (#428, #435); SCIM list filters, answered with `invalidFilter` (#414). An IdP groups claim containing a control character is refused like any malformed claim (sign-in 403).
- **Email test against a disallowed relay** records a failed test with `host_not_allowed` instead of answering 409 (#411). Requires migration **0068**.
- **Settings support/logo URLs**: the 2048-character limit applies to the stored, percent-encoded form (400 when longer), so a multibyte path no longer hits the column constraint as 409 (#419).
- **List cursors** (logs, sessions, holds, deployment history) outside PostgreSQL's timestamp range return 400 instead of 503 (#409).
- **Manual cost reconciliation** refuses incoherent operator token usage, and output tokens on an embeddings or rerank hold, with 400 instead of 503; the unknown hold is unchanged and provider settlement is unaffected (#408).
- **Report run detail and list** read the clock once per statement, so `expired` and `snapshot` always agree at the expiry boundary (#406).
- **`/v1/embeddings`** answers an oversized streamed body with the shared OpenAI `payload_too_large` error (#432). Chat Completions and Responses still use `invalid_request_error` in that case (#438).

## Behaviour changes to note

- An existing OIDC group mapping whose issuer contains a control character or whitespace can no longer be updated until the issuer is corrected; deleting it still works (#427).
- A catalog whose stored description contains a control character other than tab, LF or CR must have the text corrected on its next update (#428).
- Settings URLs that normalize to at most 2048 characters are accepted even when the raw input was longer (dot segments, default ports) (#419).

## Other changes

- Provider-reported cost reconciliation dashboard: comparison view, upload UI and acceptance documentation (#395, #397, #398, #48).
- The personal-workspace visibility rule for Platform Admins and Auditors is stated and tested: usage and cost totals only, never keys or request details (#400, #401).
- Realtime: the upstream WebSocket client moves to tokio-tungstenite 0.30, with the browser transport pinned explicitly (#16, #413).
- Tests and CI only: access-refresh test timing (#402, #407), steering pool test timing (#412, #425), contract fixtures independent of midnight UTC (#434, #437), contract-fixture sessions that outlive long runs, and a load-test image digest kept in step with the gateway image.

## Upgrade

From **v0.9.3**, replace the image and chart, using the normal drain procedure only after qualification and deployment approval. Run the migrate step: the latest migration is **0068** (`smtp_last_test_error` widened to the delivery vocabulary, no data rewrite), with **67 migration records**. There are **no runtime-grant changes**. Do not reset or recreate an existing database, run a down migration or bootstrap implicitly.

From an older release, also follow the [v0.9.3 upgrade instructions](v0.9.3.md#upgrade) and their linked requirements. Publication verification and readiness remain separate from production activation and authenticated/provider acceptance.
