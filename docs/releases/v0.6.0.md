# Open Model Gateway v0.6.0

This release is the security phase:
- **Outbound connections** follow one address policy.
- **Sign-in and dashboard sessions** are limited and visible to their owners.
- **The audit log** streams to a SIEM over a signed webhook, syslog/TLS or OTLP, with gap detection.
- **People's data** can be exported, removed early, held for legal reasons, and is kept for documented periods.
- **File-store master keys** can be retired.

A new [threat model](../threat-model.md) maps each threat to the code and tests that address it.

## Before you upgrade

These changes can stop email, sign-in, storage or clients until you act:

- **SMTP password allowlist (#140).** Move your SMTP password variable's name from `GATEWAY_SECRET_ENV_ALLOWLIST` to the new `GATEWAY_SMTP_SECRET_ENV_ALLOWLIST` (Helm `gateway.smtpSecretEnvAllowlist`). Until you do, email isn't sent. If a provider key was ever used as an SMTP password, rotate it.
- **SMTP relay allowlist (#168).** List your relay host in the new `GATEWAY_SMTP_HOST_ALLOWLIST` (Helm `gateway.smtpHostAllowlist`), or email stops with `host_not_allowed`.
- **Outbound address policy (#167).**
  - Private networks (RFC 1918, `100.64.0.0/10` including Tailscale, IPv6 ULA) are reachable only when listed in `GATEWAY_EGRESS_PRIVATE_ALLOW`.
  - A private IdP, S3-compatible store or Bedrock endpoint must be listed, or startup (OIDC) or those requests fail with a message naming the setting.
  - Loopback sidecars only work with `GATEWAY_ENV=development`.
- **Files, batches and videos in Teams and Projects are per user by default (#141).** A member's keys see only objects created with that member's keys. Set Workspace › Settings › General to Workspace-wide, or use a service-account key, for shared automation. Otherwise those reads return `404`.
- **Dashboard sessions end after 2 hours idle (#80)**, as well as 12 hours after sign-in. Change this with `GATEWAY_SESSION_IDLE_TIMEOUT` and `GATEWAY_SESSION_LIFETIME`.
- **Behind a reverse proxy, set `GATEWAY_TRUSTED_PROXIES` (#78)**, or every user shares the proxy's sign-in rate budget (default 60 a minute per replica).
- **Security headers (#142).** The dashboard can't be framed, and inline scripts are refused.
- **OIDC client (#144).** It ignores `HTTP(S)_PROXY`; the gateway must reach the issuer directly.
- **Revocations are final (#145).** SQL that clears `revoked_at` now fails.

## Upgrade guide

**Ten migrations, 0039–0048.** Most are small. These take locks worth planning for:

- **0041** rewrites `browser_sessions` under a full lock, during which dashboard requests and sign-in wait. Inference is unaffected. Check `SELECT count(*) FROM browser_sessions` first: session rows were never deleted before this release.
- **0040** builds an index on `oidc_login_attempts`; sign-in waits while it builds.
- **0043** backfills sign-in times while holding row locks on `users`.
- **0047** builds two indexes on every `audit_events` partition; audit writes wait while it builds.
- **0042** and **0048** use a 10 s lock timeout. If either times out behind a long transaction, rerun `migrate`.

The runtime role gains grants for sessions, legal holds, invitations, the audit export queue and state, and `stored_files.encryption_key_id`, so reapplying the grants is required.

1. Back up with `scripts/backup.py` and run `verify`.
2. Set the allowlists above (`GATEWAY_SMTP_SECRET_ENV_ALLOWLIST`, `GATEWAY_SMTP_HOST_ALLOWLIST`, `GATEWAY_EGRESS_PRIVATE_ALLOW`, `GATEWAY_TRUSTED_PROXIES`) in your deployment.
3. Stop every gateway replica. Mixed-schema replicas are not supported.
4. Run `open-model-gateway migrate` as the migrator.
5. Run `open-model-gateway grants apply`, then `grants verify`.
6. Start the new replicas and wait for `/health/ready`.
7. Check Admin › Settings › Email (send a test) and sign in.

**Helm:** upgrade with `--set migrations.run=true`.
- New values: `gateway.smtpSecretEnvAllowlist`, `gateway.smtpHostAllowlist`, `gateway.trustedProxies`, `gateway.sessionIdleTimeout`, `gateway.sessionLifetime`, and `networkPolicy.egress.httpsCidrs` or `httpsExceptCidrs` (#169).
- The chart's NetworkPolicy never opened SMTP or syslog ports. Add a `networkPolicy.egress.extraEgress` rule for them.

## Highlights

- **Audit export to a SIEM (#106, #107, #108, #174).**
  - Stream the platform audit log (never personal-workspace events) to one destination set by the operator: a signed HTTPS webhook, syslog over TLS (RFC 5424/5425, optional mutual TLS), or OTLP/HTTP JSON logs.
  - Delivery is at least once and in order; nothing is dropped during outages.
  - Every event carries a gap-free `seq`, and an idle export sends a signed heartbeat, so receivers can alert on lost events and on silence.
  - Turning export off is itself an exported event, even when it's done directly in the database.
  - Admin › Settings › Audit export shows status and sends a test. [Operations](../operations.md#audit-export).
- **Data controls (#74–#77).**
  - **Your profile › Your data:** download your own data as one JSON file (requests and audit entries for up to 93 days). Admins can export a person's record with only what admins already see.
  - **Remove personal data now:** run the departed-user cleanup at once for a suspended person.
  - **Legal holds:** stop all removal for a person or team.
  - **A documented retention contract** for every kind of data ([Settings](../settings.md#what-is-kept-and-for-how-long-77)).
- **Outbound address policy (#167, #168, #169).** Every outbound connection (providers, OIDC, S3, catalog, SMTP, realtime, audit export) connects only to addresses that pass the policy. Metadata, link-local and reserved ranges are always refused. Optional Helm CIDRs narrow it at the network layer.
- **Sign-in and sessions (#78–#80).**
  - Per-address sign-in limits.
  - **Your profile › Sessions:** see and end your sessions. Admins can sign a person out everywhere.
  - Idle and absolute session limits.
  - Pruning of old sessions and expired sign-in attempts.
- **File-store key rotation (#35).** `files rekey --from <old> --to <new>` re-wraps every file's data key under a new master key, without re-encrypting the contents. It is resumable and safe while serving, and `files verify` shows when an old key can be removed.
- **Restore safety (#145, #146).** Revocations can't be undone in SQL. After restoring a backup, `scripts/backup.py reapply-revocations` copies access removed after the backup onto the restored database.

## All changes

- **Audit export as OTLP logs** (#108): `GATEWAY_AUDIT_OTLP_URL` (an OpenTelemetry collector's full OTLP/HTTP logs endpoint) is the third alternative to the webhook and syslog, one destination at a time: OTLP/HTTP JSON, one LogRecord per event with the webhook's event object as body and `seq`/`id` as attributes, plus heartbeat and test records. HTTPS with the webhook's URL checks and outbound address policy. Optional headers (for example a collector token) come from the variable `GATEWAY_AUDIT_OTLP_HEADERS_ENV` names, under the webhook secret's naming rules; they are validated at startup and never shown. `OTEL_*` is never read. Records the collector refuses in `partialSuccess` are not retried (the OTLP rule): they are counted (`gateway_audit_export_rejected_records_total`), shown as `otlp_rejected`, and receivers see the `seq` gap. Settings › Audit export shows "OpenTelemetry (OTLP)". [Operations](../operations.md#otlp-logs).
- **Audit export over syslog/TLS** (#107): `GATEWAY_AUDIT_SYSLOG_URL=syslog+tls://host[:port]` (default port 6514) is the alternative to the webhook: one RFC 5424 message per event with RFC 5425 octet counting, TLS only (the public roots, or only `GATEWAY_AUDIT_SYSLOG_CA_FILE`), optional mutual TLS (`GATEWAY_AUDIT_SYSLOG_CLIENT_CERT_FILE`/`_KEY_FILE`), through the outbound address policy. Same queue, `seq` numbers and heartbeats. Setting both URLs, `off` in one and a destination in the other, the webhook secret with only syslog, or an unreadable TLS file stops startup. Syslog has no acknowledgement: a receiver that fails after reading can lose events (a `seq` gap); use the webhook when you need acknowledged delivery. Settings › Audit export and its status (`transport`) show which is in use. [Operations](../operations.md#syslog-over-tls).
- **Audit export gap detection** (#174): every exported event now carries `seq`, a per-installation number that grows by one per event and is never reused, and an idle export sends a signed heartbeat every minute with `next_seq`. Receivers can alert on gaps (lost, archived or removed events) and on silence. Turning export off or on now writes its `audit_export.disabled`/`enabled` event through a database trigger, so even a direct change of the export state is exported. Migration 0048 adds the counter, write-once triggers and the marker triggers (with a 10 s lock timeout: rerun `migrate` if a long transaction held `audit_export_state`); the runtime role gets `UPDATE(seq)` on the queue and `UPDATE(next_seq,last_heartbeat_at)` on the export state. During a rolling upgrade a replica still on the old version can deliver events without `seq`; receivers should start gap checks after the upgrade.
- **Retire a file-store encryption key** (#35): `open-model-gateway files rekey --from <old> --to <new> [--dry-run]` re-wraps every live file's data key under the new master key (contents are copied back unchanged, never decrypted), one atomic replace per object, resumable and safe while serving. `files verify` now reports `active_key_id` and `retired_key_ids_in_use`, the decrypt-only keys you can't remove yet. The runtime role gets `UPDATE(encryption_key_id)` on `stored_files`. Rotation procedure in [operations](../operations.md#file-store-encryption-keys).
- **Download your data** (#74): Your profile › Your data exports your profile, memberships, key details, sessions, files list, and your requests and audit entries for up to 93 days as one JSON file with a SHA-256 header; never key secrets, prompts, responses or file contents. Platform Admins and Auditors can export a person's record with only what admins already see. Audited and limited to 3 an hour. Migration 0047 adds two indexes on `audit_events` (built on every month partition; a large audit log takes a while and blocks audit writes meanwhile) and 0046 one on `stored_files`.
- **Retention contract** (#77): [Settings › What is kept, and for how long](../settings.md#what-is-kept-and-for-how-long-77) lists every kind of data, how long it's kept, what removes it and how legal holds apply. Compaction also clears the client session id and app (the docs said only error code and latency) and is tested to be bounded, resumable and never to change costs or the ledger.
- **Remove personal data now** (#76): Platform Admins can run the departed-user cleanup at once for a suspended person (refused on legal hold). Cleanup now also clears the person's address on old invitations and alert recipients and the names of files they uploaded; history keeps the user id as its pseudonymous reference. [Identity](../identity.md#what-cleanup-removes-and-keeps-76) lists what is removed and kept. The runtime role gets `UPDATE(email)` on `workspace_invitations`.
- **Legal holds** (#75): Platform Admins place a hold on a person or a team/project (from its page, with a reference code) and release it in Admin › Records › Legal holds. While held, nothing of that scope is removed: departed-user cleanup, request-log compaction, file expiry and `archive partition` wait or refuse. Holds grant no access, are audited, and are released, never deleted. Migration 0045; the runtime role gets `SELECT`, `INSERT` and `UPDATE(released_at, released_by_user_id)` on `legal_holds`.
- **Audit export to a SIEM** (#106): set `GATEWAY_AUDIT_WEBHOOK_URL` and `GATEWAY_AUDIT_WEBHOOK_SECRET_ENV` to stream the platform audit log (never personal-workspace events) as signed HTTPS deliveries, at least once, in order, with nothing dropped during outages. Operator-controlled: only `GATEWAY_AUDIT_WEBHOOK_URL=off` turns it off (a replica without the setting changes nothing), and the on/off transitions are exported events. The secret's variable may not be on a provider or SMTP allowlist. Admin › Settings › Audit export shows status and sends a test. Format `omg.audit.v1` ([operations](../operations.md#audit-export)). Migration 0044 adds the export queue and its trigger on `audit_events`; the runtime role gets the queue and status grants (audit stays append-only). New metrics `gateway_audit_export_*`.
- Helm: `networkPolicy.egress.httpsCidrs` narrows outbound 443 to chosen networks, or `httpsExceptCidrs` keeps it off chosen ranges such as the private ones (#169). The default is unchanged (443 to any address). SMTP has never been opened by the chart: add an `extraEgress` rule for your relay's port. [Kubernetes › Outbound traffic](../kubernetes.md#outbound-traffic) explains aligning the NetworkPolicy with `GATEWAY_EGRESS_PRIVATE_ALLOW`.
- **Breaking: SMTP relay hosts need operator approval** (#168). The relay set in Admin › Settings › Email must be listed in the new `GATEWAY_SMTP_HOST_ALLOWLIST` (Helm `gateway.smtpHostAllowlist`), or email stops: status shows `host_not_allowed` and sends, including the test email, fail with that reason before the password is read. List your relay before upgrading. The relay and the OpenAI realtime WebSocket now also go through the outbound address policy (#167); a listed loopback relay stays allowed.
- **Outbound address policy** (#167, part of #33). Every outbound HTTP connection (providers, OIDC, S3, catalog) is checked at DNS resolution and connects only to an address that passed: never metadata, link-local or reserved ranges; loopback only with `GATEWAY_ENV=development`; private networks (RFC 1918, `100.64.0.0/10` including Tailscale, IPv6 ULA) only when listed in the new `GATEWAY_EGRESS_PRIVATE_ALLOW`. **Behaviour change:** an installation that reaches a private IdP, S3-compatible store or Bedrock/S3 private endpoint must list its network, or startup (OIDC) or those requests (S3, Bedrock) fail with a message naming the setting. Also affected: loopback sidecars (a local MinIO or proxy) outside `GATEWAY_ENV=development`; IP-literal S3 or Bedrock endpoints now stop startup instead of failing per request; IPv6-only clusters keep working through NAT64. List only your tailnet addresses, not all of `100.64.0.0/10`. Configured IP-literal endpoints are checked at startup. New metric `gateway_egress_denied_total{purpose}`, counted only when no allowed address remains. AWS credential lookups (instance metadata, ECS/EKS, STS) are not covered.
- **Behaviour change: dashboard sessions now end after 2 hours without activity** (#80), as well as 12 hours after sign-in. Set `GATEWAY_SESSION_IDLE_TIMEOUT` (`off`, or `15m` up to the lifetime) and `GATEWAY_SESSION_LIFETIME` (`15m` to `7d`) to change them (Helm `gateway.sessionIdleTimeout`, `gateway.sessionLifetime`). Existing sessions keep their expiry and get the idle limit from their next recorded activity (recorded at most every 5 minutes, so a session can end up to 5 minutes before the idle timeout); a longer setting never revives an ended session, and a shorter one doesn't shorten existing sessions (sign people out instead). Without SCIM, a longer lifetime also delays when a removed IdP group takes effect. Maintenance now deletes expired sign-in attempts (every minute) and sessions that ended more than 30 days ago (hourly). Migration 0042 adds `browser_sessions.idle_expires_at` and `users.first_signed_in_at`/`last_signed_in_at` (metadata only, with a 10-second lock timeout so admissions never queue behind it; retry the migration if it times out), and 0043 backfills the sign-in times from existing sessions (row locks on `users` until it commits: admission of affected users' keys waits that long), so "First signed in" and "Last sign-in" survive cleanup. The first hourly cleanup clears a large pre-existing sessions table at 10,000 rows an hour; the runtime role gets `DELETE` on `browser_sessions` and `UPDATE` on the new columns.
- Your sessions (#79): Your profile › Sessions lists where you're signed in (browser and OS family, sign-in and last-active times; no IP address or raw user agent) and signs one or all other sessions out. Platform Admins see a person's session count and can sign them out everywhere without suspending them. New API: `GET /me/sessions`, `DELETE /me/sessions/{id}`, `POST /me/sessions/revoke-others`, `POST /platform/users/{user}/sessions/revoke`. Migration 0041 adds `id`, `last_seen_at` and `client_label` to `browser_sessions`. The `id` default rewrites the table and builds a unique index under a full table lock: every dashboard request and sign-in waits until it finishes (inference is unaffected). Session rows have never been deleted (#80), so check `SELECT count(*) FROM browser_sessions` first and plan a short window for a large table. The runtime role gets `UPDATE(last_seen_at)`.
- Sign-in abuse controls (#78): per-address limits on sign-in starts and callbacks (`GATEWAY_LOGIN_RATE_PER_MINUTE`, default 60 a minute, per replica), and at most 10,000 pending sign-in attempts installation-wide (503 beyond). Refusals return 429 or 503 with `Retry-After` and store nothing. Behind a reverse proxy, set `GATEWAY_TRUSTED_PROXIES` (Helm `gateway.trustedProxies`) to its addresses, or every user shares the proxy's budget. New metric `gateway_auth_throttled_total`. Migration 0040 adds an index on `oidc_login_attempts(expires_at)`; it is a plain `CREATE INDEX`, so sign-in waits while it builds (the table holds only sign-in attempts, but they have never been deleted).
- An admin suspension is audited as `user.suspended` (with the reason) and a reactivation as `user.reactivated`, instead of `user.updated` without detail. `user.updated` now flags `email_changed` or `oidc_link_changed`, never the values, and is written only when something changed (#158).
- After a restore, `scripts/backup.py reapply-revocations` copies every revocation (keys, grants, sessions, invitations) and suspension (users, keys, service accounts, workspaces) from the old database onto the restored one, so access removed after the backup stays removed (#146). It's a dry run without `--yes`, applies in one transaction and refuses a different installation. The restore runbook in docs/operations.md now covers revocations, sessions and lost spend.
- Revocations are final in the database: migration 0039 adds triggers that refuse clearing or changing `revoked_at` once set on API keys, membership and platform role grants, browser sessions and invitations, for every role (#145). Hand-written SQL that "un-revokes" a key or grant now fails; issue a new one instead.
- The OIDC client (discovery, token exchange, JWKS) no longer uses ambient `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` or implicit retries, like every provider client (#144). If sign-in only worked through such a proxy, allow the gateway to reach the issuer directly.
- CI pins every GitHub Action by commit SHA and the `Dockerfile` build images by digest, and `npm run test:supply-chain` fails CI on any unpinned one (#143).
- Every response now carries a Content-Security-Policy, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer` (#142). The dashboard's policy allows only its own scripts, styles, fonts and API (no inline script or `eval`) and can't be framed; API and file responses get `default-src 'none'`. If you embed the dashboard in a frame or load it through a proxy that injects scripts, that no longer works.
- **Breaking (#141):** Teams and Projects have a new setting, **who sees files, batches and videos** (Workspace › Settings › General; `object_visibility` on `GET/PATCH /api/v1/workspaces/{ws}`, migration 0038). **Per user**, the default for new and existing shared workspaces: a regular member's API keys and dashboard see only objects created with that member's keys; service-account keys and workspace owners/admins see everything. **Workspace-wide:** every key sees everything. In both modes only the creator, an owner/admin or a service-account key may delete or cancel (`403`); an object the caller can't see returns `404`, also as a batch's `input_file_id`. Before, any key of a shared workspace could read, delete or cancel every member's objects through `/v1/files`, `/v1/batches` and `/v1/videos`.

  **Upgrade:** run the migration and reapply the runtime grants (`object_visibility` is added to the runtime role's `UPDATE` on `workspaces`). Clients that read other members' objects with a member key get `404` until a workspace admin sets the workspace to Workspace-wide; use a service-account key for workspace-wide automation.
- rustls 0.23.45 → 0.23.46 for RUSTSEC-2026-0346 (session `Debug` output exposed TLS secrets), -0347 (data sent to the outer server after an ECH rejection), -0348 (unbounded Brotli certificate decompression) and -0349 (an unauthenticated ServerHello could downgrade later connections to classical key exchange).
- **Breaking (#140):** the SMTP password reference now resolves only from the new `GATEWAY_SMTP_SECRET_ENV_ALLOWLIST` (Helm: `gateway.smtpSecretEnvAllowlist`), never from the provider list `GATEWAY_SECRET_ENV_ALLOWLIST`. Before, a Platform Admin, who chooses the SMTP host, could set the SMTP password to a provider key reference and send that key to a mail server they control. The gateway refuses to start if a name is on both lists, or if the SMTP list names one of its own credentials (`DATABASE_URL`, `GATEWAY_*`, `AWS_*`, `GATEWAY_OIDC_CLIENT_SECRET`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`).

  **Upgrade:** move your SMTP password variable's name from `GATEWAY_SECRET_ENV_ALLOWLIST` to `GATEWAY_SMTP_SECRET_ENV_ALLOWLIST`. Until you do, invitations and alerts are not emailed (Settings › Email shows the reference as not allowed). If a provider key was ever used as an SMTP password, rotate it.
- New [threat model](../threat-model.md) (#32): STRIDE threats by area with the code and tests that mitigate each, residual risk, and a gaps table mapped to follow-up issues, for code reviews and the independent security review (#61).

## Verification

- Homelab cluster run (#25): a PgBouncer restart under load failed 2 of 5,400 requests and a dropped LISTEN connection none; primary failover promoted the standby in 18 s with the chart's 15 s smart shutdown. Accounting stayed exact through every fault. A second write outage after a 2-instance failover is tracked in #149, and the remaining steady-load stalls in #132. See [HA PostgreSQL](../postgresql-ha.md).

## Fixed

- Settings pages keep "Settings saved." when the refetch after a save brings the saved values back (#164).

## Known limitations

- **No certified capacity number yet.** The steady-load stalls (#132) and a second write outage after a 2-instance failover (#149) are still open.
- Syslog messages aren't signed: their authenticity depends on the receiver requiring the client certificate. OTLP has no client-certificate option.
- IdP-initiated (back-channel or front-channel) logout is not implemented (#162).
- Guardrails are designed (#36) but not built (#181).
- The Helm chart is still **beta**.
- Development software: not accepted for production. Live SCIM acceptance (#60) and an independent security review (#61) remain open.

## Verifying the images

The image is `ghcr.io/ncecere/open-model-gateway`, tagged `v0.6.0`, `v0.6` and `latest-release`. Deploy by digest: the digest is in the GitHub Release, its `open-model-gateway-v0.6.0.digest.txt` asset, and the workflow's job summary.

Verify the signature with [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) **v3.0 or newer** (keyless, GitHub Actions OIDC). The signature is stored in cosign v3's bundle format, so cosign v2 reports "no signatures found":

```sh
cosign verify ghcr.io/ncecere/open-model-gateway@sha256:<digest> \
  --certificate-identity https://github.com/ncecere/open-model-gateway/.github/workflows/image.yml@refs/tags/v0.6.0 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

The signature covers the multi-arch index, and so every tag that points at it. The SBOM (SPDX) and build provenance are attached to the image as attestations:

```sh
docker buildx imagetools inspect ghcr.io/ncecere/open-model-gateway@sha256:<digest> --format '{{ json .SBOM }}'
docker buildx imagetools inspect ghcr.io/ncecere/open-model-gateway@sha256:<digest> --format '{{ json .Provenance }}'
```

The Release also carries each platform's SBOM as `open-model-gateway-v0.6.0-linux-<arch>.sbom.spdx.json`, with `checksums.txt` (`sha256sum -c checksums.txt`). The Helm chart (`deploy/helm/open-model-gateway/`, chart version 0.6.0) defaults `image.tag` to `v0.6.0`; pin `image.digest` to the verified digest before a real rollout.
