# PostgreSQL governance

## Management integration contract

Scoped policy mutations lock the consuming organization `FOR NO KEY UPDATE` and recheck live authority inside the transaction. Global catalog/pricing changes use the exclusive catalog transaction lock; admission acquires its shared form before the organization lock. Finishes/reconciliation retain organization serialization. Management credentials only; inference tenant IDs come from authentication, not caller payloads.

Base migration: `0004_governance.sql`; platform ownership/ceiling separation: `0007_platform_catalog.sql`. See [platform administration](platform-administration.md).

- `governance_policies`: `id UUID`, `organization_id UUID`, `scope TEXT` (`organization`, `workspace`, `key`), nullable `workspace_id UUID`, nullable `api_key_id UUID`; nullable positive BIGINT `requests_per_minute`, `tokens_per_minute`, `concurrent_requests`, `monthly_budget_microusd`. Organization scope requires both IDs null; workspace scope requires workspace only; key requires both. One row per scope target (partial unique indexes). All-null limits mean no additional restriction at that scope; inherited limits still apply. Policy CRUD is mutable under the org lock.
- `platform_organization_policies`: one platform-admin-controlled ceiling per consuming organization, with the same nullable positive limit fields. Organization admins cannot write this layer.
- `deployment_prices`: `id UUID`, optional legacy `organization_id UUID` provenance, `deployment_id UUID`, nonnegative BIGINT `input_microusd_per_million`, `output_microusd_per_million`, positive BIGINT `input_token_limit`, `output_token_limit`, `created_at TIMESTAMPTZ DEFAULT clock_timestamp()`. Append versions only; UPDATE/DELETE/TRUNCATE are rejected. Latest version ordered by `created_at DESC,id DESC`. Server generates ID/time; never accept operator backdating. USD only.
- `governance_reservations`: `execution_id UUID` PK, organization/workspace/key/deployment IDs, nullable `price_id`; `admitted_at`, `minute_start`, `month_start`, `lease_expires_at` timestamptz; state `pending|unknown|settled`; nullable BIGINT `reserved_tokens`, `held_microusd`, `actual_microusd`, `input_tokens`, `output_tokens`. Monetary history is retained permanently by default.
- `monetary_ledger`: UUID `id`, `organization_id`, `execution_id`; kind `hold|unknown|settlement|reconciliation`; nullable BIGINT `amount_microusd`, `input_tokens`, `output_tokens`; nullable `evidence` reference; `created_at`. Append-only, unique kind per execution. Events are NOT additive: settlement/reconciliation replaces the earlier hold in the reservation projection. Unknown entries do not release holds.

Public Rust entry points:

```text
admit_for_deployment(&Store, &ExecutionStart, &ChatRequest, lease_seconds: i64, &Deployment) -> Result<(), InferenceError>
admit(&Store, &ExecutionStart, &ChatRequest, lease_seconds: i64) -> Result<(), InferenceError> // accounting/test helper; live authorization and target checks, no cached-target comparison
finish(&Store, &ExecutionFinish) -> Result<(), InferenceError>
reconcile_expired(&Store, limit: i64) -> Result<u64, InferenceError>
resolve_usage(&Store, org: Uuid, execution: Uuid, usage: Usage, evidence: &str, actor: Uuid) -> Result<(), InferenceError>
```

`resolve_usage` requires complete usage and a nonempty evidence reference <=200 characters (no prompts, response content or secrets). The caller authorizes a platform operator and applies personal-workspace privacy before calling. The ledger transaction also rechecks current operator authority, active organization/workspace, and personal ownership after acquiring its lock; it holds shared actor/workspace locks through commit. Audit `usage.reconciled`, execution target, workspace, actor and monetary reconciliation commit atomically. Identical resolved usage is idempotent; conflicting values fail closed. Execution starts include `root_request_id` and `attempt_number` (1–3); each upstream attempt has its own execution ID and admission. Existing execution rows are backfilled with root ID equal to execution ID and attempt 1. A unique root/attempt index prevents duplicate attempt accounting.

## Enforcement and accounting

Platform organization ceilings, editable organization restrictions, workspace (team/project/personal) and key limits all apply. Unset child limits share the parent's remaining allowance; explicit child caps are additional limits, not reserved slices. Rotating a key preserves its policy and consumption lineage (minute/month counters and active holds); current and revoked predecessor IDs resolve to the same policy. Creating a distinct key starts a separate key scope. Use organization/workspace ceilings for overall control—per-key limits are not per-user ceilings, and users can issue separate keys. PostgreSQL serializes admissions across replicas. Fixed minute windows and calendar months use UTC database wall-clock time sampled AFTER acquiring the lock, not process time or transaction start time. Retries count as separate admitted attempts. Denials do not consume quota.

Admission revalidates active keys, users/service accounts, memberships, workspace ownership and current organization/delegated model grants under locks. Production admission additionally verifies the cached deployment target/credential reference/endpoint/region still match current enabled configuration while holding shared target rows under the consuming organization lock. Drift fails closed before dispatch rather than pricing one target and executing another.

Every priced request must explicitly supply `max_output_tokens`, positive and no greater than its configured price version output limit. Reserve the FULL configured hard provider input ceiling plus requested maximum output; no tokenizer estimate, request mutation, or assumed free provider errors. Token/budget policies require a price version and these bounds. Without a price and without token/budget policies, existing requests remain functional without an output limit and their monetary cost remains unknown, never zero.

Operators must configure an accurate HARD provider input ceiling and prices. Provider routing/configuration must actually enforce that ceiling. These reservations are not an invoice guarantee: unreported tokens, provider price changes, cached/reasoning token categories, extra provider fees, and inaccurate ceilings can differ from gateway accounting. A deployment configuration change must be paired with an accurate new immutable price version under the same exclusive catalog configuration lock. Do not reuse an inaccurate old version.

USD-micro cost is the sum of separately rounded-up input and output components: `ceil(tokens * microusd_per_million / 1_000_000)`. Integer i128 intermediates; values outside BIGINT fail closed. Successful complete usage settles against the pinned price, including known cost above the reservation. Such overspend naturally blocks subsequent admissions. Minute token reservations are conservatively not refunded; known usage above a reservation raises minute consumption. Partial/unknown usage and failed/cancelled attempts retain the FULL budget hold until explicit evidence-backed reconciliation. If reported token categories already imply a cost above that hold, the unresolved hold grows to that known lower bound; missing categories are still unknown, not free. The unknown ledger event records the priced lower bound, while the reservation projection retains the greater of original hold and lower bound. Previously admitted unpriced unknown usage in a month blocks later budget enforcement rather than treating it as free. Any unbounded prior reservation in the current minute also blocks a newly enabled token quota, even if some actual usage is available. Migration backfills every legacy execution into a reservation and unknown ledger event, preserving its original minute/month; legacy pending calls receive a 3605-second lease from their original start. Configure pricing BEFORE enabling traffic: unpriced history cannot be retroactively priced through usage reconciliation, because it has no pinned rate. It blocks a newly enabled monthly budget until the next UTC month (token quotas until the next minute); never work around this by deleting history.

Budget usage is `sum(coalesce(actual_microusd,held_microusd))` per scope and admission month. Holds never silently expire. A call spanning midnight/month rollover remains attributed to its admission minute/month, as does later settlement. Current-month policies are not a lifetime credit facility.

Concurrency counts only pending, unexpired leases. The engine MUST set a lease longer than its entire active-work deadline, including dispatch, retries for this attempt, streaming and teardown margin. There is no heartbeat: work must never continue after its lease. Expiry reconciliation marks pending executions cancelled with `lease_expired`, releases concurrency and retains unknown cost holds. Late finish cannot erase an expired hold; explicit reconciliation is required.

Metadata retention must never delete prices, ledger, reservations, unresolved holds, or execution rows referenced by those records. No automatic monetary retention/deletion is implemented. Retain accounting history or design an independently audited archival scheme. `GATEWAY_EXECUTION_DETAIL_RETENTION_DAYS=30..3650` optionally compacts display metadata of old **settled** executions hourly in batches of 1000: public alias/provider become `[retained-accounting]`, transient error/latency detail is removed, and `details_redacted_at` is recorded. Usage, state, ownership references, prices, holds and ledger remain intact. Unknown/pending records are never compacted. Default is disabled; `compact-history --older-than-days N --limit 1000` runs one explicit batch.

## Tests

`DATABASE_URL=... cargo test -p open-model-gateway --all-features governance::` uses real PostgreSQL databases created by SQLx (the test role needs database creation permission). Coverage includes racing admissions for each independent quota, hierarchical scope isolation and tenant constraints, immutable price pinning, settlement idempotency, missing-usage and provider-failure holds, increased holds for partial overspend, expired leases, evidence reconciliation with atomic audit rollback, overflow, pre-governance migration backfill, and UTC minute/month attribution. No paid provider calls are made.
