## 15. Execution model and definition of done

1. One bounded implementation issue per worker/branch. Parent epics are acceptance ledgers, not giant implementation branches. Parallelize independent domains; serialize shared engine/types/schema ownership and all coordinator Cargo/database operations.
2. Branch from current main, add the failing regression first, then the smallest complete implementation. Update API contracts/inventories and documentation in the same relevant change.
3. Use explicitly selected fresh databases; update/test runtime grants and live authority. Existing installations require authorized backup/migrate/restore/cutover procedures, never an implicit reset.
4. Prove the changed flow against a running gateway, including refusal, cancellation, concurrency and accounting cases. UI means real browser tests/screenshots; mock providers never become a claimed live-provider certification.
5. Every change gets review; security-relevant changes get two separately briefed independent reviews, one critical/adversarial. Coordinator reads every diff and reruns doubtful checks.
6. Run the complete required local gates on the exact final combined commit before push/PR. Merge only through a protected PR with all required CI green. CI, PR and issue are the record.
7. Close an issue only after its own acceptance and required merge/release evidence; keep external blockers explicit. A parent needs child proof plus a parent-only scope sweep.
8. Cut coherent pre-v1 releases after qualification; candidate/staging and production activation/acceptance are distinct statuses. No paid accounts/calls, new cloud resources, other-repository changes or production actions are implied by approving this planning document.
