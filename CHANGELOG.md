# Changelog

Notable changes to Open Model Gateway, one entry per release. Each release's notes (highlights, migrations, new environment variables, behaviour changes, upgrade steps and known limitations) are in [`docs/releases/`](docs/releases/).

The project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Before 1.0, minor releases may include breaking changes; the release notes say how to adapt.

## [Unreleased]

## [0.4.0] - 2026-10-10

**Helm chart** (scale phase P7, `deploy/helm/open-model-gateway/`, chart version 0.4.0). Gateway Deployment (replicas or HPA, PDB, topology spread, non-root UID 10001, read-only root filesystem, no capabilities, seccomp, no service-account token, `httpGet` startup/liveness/readiness probes, a `preStop sleep` paired with the existing drain behaviour); a pre-install/pre-upgrade migration Job that runs `open-model-gateway migrate` as a separate migrator Secret (never the runtime role, never automatic in `serve`) and then applies `deploy/staging/runtime-grants.sql` through a PostgreSQL client container (no Rust `apply-runtime-grants` subcommand yet; documented in [Kubernetes](docs/kubernetes.md#migration-job-and-runtime-grants)); an optional CloudNativePG `Cluster` (2 instances, synchronous replication, `local-ssd` storage, anti-affinity, PostgreSQL 17 from `ghcr.io/cloudnative-pg/postgresql`, tuned parameters, managed `gateway_migrator`/`gateway_runtime` roles backed by operator-created Secrets, never chart-generated) and `Pooler` (PgBouncer, transaction mode, `max_prepared_statements: 200`), with an external-database mode as the default; Secrets-by-reference for database URLs, OIDC and provider keys (file-mounted `_FILE` secrets) and file-store keys, a ConfigMap for non-secret env; default-deny NetworkPolicy with Traefik ingress and DNS/Postgres/443 egress, a configurable Ingress, Service, optional ServiceMonitor/PodMonitor; a `loadtest` values profile (`mock-upstream` + `loadgen`) for P8. Validated with `helm lint`/`helm template` across four profiles, `kubeconform` against Kubernetes 1.36 schemas, and a real `kubectl apply --dry-run=server` against a live CloudNativePG 1.30.1 operator (all resources passed its admission webhooks; nothing was created). New `npm run test:helm` (rendered-output assertions) and a CI `helm` job. Docs: [Kubernetes](docs/kubernetes.md).

Scale work, phase P0 (measurement): `gateway_admission_seconds` and `gateway_settlement_seconds` histograms by phase and outcome (including lock waits); `tools/mock-upstream`, `tools/loadgen` (open-loop runs across replicas, and a seeder that only targets `omg_loadtest*` databases); a laptop load-test stack (`deploy/loadtest/compose.yaml`: PostgreSQL 17, PgBouncer, three replicas) driven by `scripts/loadtest.py`; a capacity baseline, PgBouncer guidance and a `pg_stat_statements` guide in [operations](docs/operations.md). Phase P1: reports, usage, logs, `/me` and `/v1/models` read from REPEATABLE READ READ ONLY snapshots without the installation or catalog lock (authorization inside the snapshot), with an optional reporting replica (`GATEWAY_REPORTING_DATABASE_URL`, `GATEWAY_REPORTING_MAX_LAG_SECONDS`). Phase P2: maintained per-minute and in-flight counters for workspace and key scopes (migration 0024), the `held_unknown` split in budget totals (0025), price and bounds resolved before the installation lock (about 14 → 6 round trips under it), budget alerts and the metrics gauge on totals, change-only routing health writes and batched `SKIP LOCKED` lease reconciliation; laptop ceiling about 80 → 205 ok/s. Fix: a request cancelled just after `BEGIN` could return its pooled connection still inside a transaction (sqlx); transactions now begin in a detached task (`db.rs`, direct `Pool::begin` is a clippy error), and 503 storage errors log the request id and SQLSTATE.

**Breaking: installation-wide limits removed** (migration 0026). No installation budget (any period) and no installation requests/tokens per minute, requests at once or jobs at once; limits exist only on workspace-type defaults, platform workspace overrides, tighten-only workspace caps and keys, all still hard limits. Admission and settlement no longer touch any installation limit row (no installation `budget_totals` scope, no installation rate scan). `GET/PUT /platform/installation/policy` return `410 reason:"installation_limits_removed"`; `installation_budgets` and the access `platform` layer row are gone. New non-blocking **Installation spend** alert (`spend_threshold`); installation budget alert rules are converted to it (thresholds and recipients kept). Upgrade: migrate, reapply runtime grants, `budget verify`. Notes: [`docs/releases/v0.4.0.md`](docs/releases/v0.4.0.md).

**Scoped admission** (scale phase P3, migration 0027). Admission and settlement no longer take the installation row lock. They follow one canonical, deadlock-free order: the shared catalog lock, transaction advisory locks of the key's workspace type, workspace, user and key lineage (shared in admission, exclusive in every management change of that scope), the reservation row, then the workspace's and lineage's `budget_totals`, minute and in-flight counter rows in primary-key order. No `FOR SHARE` on authority rows in the hot path. Every management, SCIM, sign-in and lifecycle change that can affect admission takes its scope locks up front (site table in [governance](docs/governance.md#authority-change-sites)); database triggers back this up for every code path, and an audit mode in the test suite refuses out-of-order or missing locks. Governance transactions aborted as deadlock victims (40P01 only) are re-run at most twice, never repeating upstream work (`gateway_lock_deadlock_retries_total`). `GATEWAY_ADMISSION_MODE=global` restores the former protocol for one release. Revocation stays live; budgets stay exact. Laptop ceiling about 240 → 1,050–1,080 ok/s, and three replicas now beat one (998 vs 814 ok/s at 1000/s); one hot workspace tops out near 210–250/s ([operations](docs/operations.md#scoped-admission-p3)).

**Per-replica caches and leased background work** (scale phases P4 and P5, migrations 0028 and 0029). Each replica caches what it reads before admission: key metadata by token hash (never the secret; engine routes only, files/batches/videos/realtime stay live), candidate deployments, routing snapshots, passive health (1 s) and immutable prices. Deferred triggers bump a per-domain version in `config_versions` (catalog, access, keys, policy, settings) once per transaction at commit and `NOTIFY omg_config`; replicas LISTEN on a dedicated session connection (`GATEWAY_LISTEN_DATABASE_URL`, default `DATABASE_URL`; never transaction-mode PgBouncer) and poll the versions every second; caches are bypassed when the versions are unconfirmed for 3 s, and `GATEWAY_CONFIG_CACHE=off` turns them off. Admission still re-checks authorization, entitlement, catalog, the latest price and policies live under its locks, so revocation on one replica blocks new upstream work on every replica immediately (tested on a deliberately stale replica for eleven kinds of change); invalidation through LISTEN took 5–10 ms. Admission reads the latest price id with its deployment check (one round trip less). Singleton jobs (account cleanup, compaction, counter pruning and storage usage, alert evaluation, the file sweeper, the installation-wide reservation gauge) run on one replica at a time under `work_leases` rows with fencing epochs (a stale leader cannot commit; takeover after expiry, immediate on graceful shutdown); queues keep `SKIP LOCKED`. Account cleanup no longer takes the installation row every minute unless an account is due. New metrics `gateway_cache_lookups_total`, `gateway_config_*`, `gateway_work_lease*` and `gateway_background_runs_total`. Laptop results: one replica at pool 10 serves 998/s at 1000/s offered (814/s before), three replicas 1,340/s at 1500/s (1,051/s with caches off in the same session) ([operations](docs/operations.md#caching-and-background-work-p4p5)).

**History partitions, hourly rollups and archival** (scale phase P6, migrations 0030–0033). Executions, reservations and the ledger (which gains `admitted_at`, so an attempt's rows share its admission month), audit events and storage usage hours are range-partitioned by UTC month. Existing rows are attached as a legacy partition without a rewrite (prebuilt keys, `CHECK … NOT VALID` → `VALIDATE` → `ATTACH`; `partitions prepare` builds the keys online before the drain; every step resumable); only the ledger is copied once under a `SHARE` lock with a count/sum/hash check. Keys include the partition key; new ids are UUIDv7; admission times can no longer move; `async_jobs`/`realtime_responses` references to history became insert-time checks. A leased `partitions` job keeps 3 future months (`GATEWAY_PARTITIONS_AHEAD_MONTHS`) through a narrow `SECURITY DEFINER` function (no runtime DDL, no default partition: writes outside every month fail closed) and raises the built-in `partitions_missing` incident below 2 months; `partitions ensure|status` for operators; readiness accepts partitions of known parents only. Hourly usage rollups (exact integer sums, unknown kept apart, change markers keep them exact in every snapshot) serve Usage Explore over ≥ 7 days and the spend-spike baseline; parity-tested against raw scans (`GATEWAY_USAGE_ROLLUPS=off` reads raw). Operator-only `archive partition <history|audit|storage> <YYYY-MM|legacy>` exports a checksummed CSV set and detaches a closed month only past retention (`GATEWAY_HISTORY_RETENTION_MONTHS`, 25) and without pending or unknown cost; `budget verify` adds archived contributions. Measured: converting 2 M seeded attempts took 27.7 s with no read waiting longer than 5 ms and at most 0.68 s of exclusive locking; throughput without readers is unchanged from 2 M to 10 M attempts of history (three replicas 998.5/s at 1000/s offered on both); one hot workspace or key tops out lower than before (about 160–206/s, was 202–250/s). Decision gate D3 failed: foreign keys from history to hot parent rows create a median 1.3 and up to 5.4 MultiXact members per request (dropping them in an experiment removed all), a follow-up. Notes: [`docs/releases/v0.4.0.md`](docs/releases/v0.4.0.md).

**History parent checks** (scale decision gate D3, migration 0034). Foreign keys from executions and reservations to workspaces, keys, deployments, price versions, cost centers and batch jobs locked those parent rows `FOR KEY SHARE` on every insert, so concurrent admissions created MultiXacts (P6: up to 10.9 % of the 2^32 member space per day at 1,000 requests/s). They are replaced by `BEFORE INSERT` triggers that check the same scoped relationships (a key of the execution's workspace, a price version of the reservation's deployment, a batch job of the same workspace) with plain reads, which is race-free because those parents can no longer be deleted, truncated or re-keyed by any role (triggers; the runtime had no such privilege already). Reservation → execution and ledger → reservation keys stay. Settlement, the totals trigger and the expired-lease read now name the admission month, so they touch one partition instead of probing all, and settlement writes the execution outcome, reservation and ledger entry in one statement (one round trip while the scope's totals rows are held). New `history verify` command and hourly leased `history_verify` job with the built-in critical `history_orphans` incident and `gateway_history_verify_findings` gauge; operations guidance for `mxid_age` and `pg_stat_slru`. Measured on the laptop stack: 0 MultiXacts in every run (same-session P6 control: up to 5.2 members per request, 10.5 %/day; 10 M attempts, three replicas, 1,000/s: 39,330 → 0); one hot workspace serves 243–255/s (P6 160–178, P4/P5 202–250); saturation is back at P4/P5 levels; 0034 took 43 ms on 10 M attempts. Notes: [`docs/releases/v0.4.0.md`](docs/releases/v0.4.0.md).

**Per-scope admission ceiling visibility** (scale follow-up to P3; per-scope shards, P3b, stay deferred; migration 0036). One workspace or key lineage serializes its own admissions on its totals rows and tops out at a few hundred requests/s. New low-cardinality metrics `gateway_scope_lock_wait_seconds{lock,path}` (authority locks vs the scope's totals/counter rows; admission vs settlement) and `gateway_scope_lock_waiting{path}`, with no workspace or key labels, and an example `GatewayScopeLockWaitHigh` Prometheus rule. New installation-only alert rule kind **Admission ceiling** (`admission_ceiling`): per workspace and key lineage, admissions at or above a rate in every minute of a 5–10 minute window, and/or a lock-wait p95 at or above 10–2500 ms (from per-minute, per-scope wait counts each replica flushes to `admission_lock_waits` every 5 s; pruned after an hour). The incident names a Team/Project for Platform Admins only (Auditors see it without the workspace), a personal workspace only as "a personal workspace", never a key; email to Platform Admins only. Docs: [operations](docs/operations.md#per-scope-admission-ceiling), [alerts](docs/alerts.md#rule-kinds).

**Autovacuum of reservation partitions** (migration 0035_counter_autovacuum). Every admission walks the dead `governance_leases` index entries settled reservations leave behind until vacuum removes them; with the defaults a large month partition waited for 20 % dead rows and could skip index cleanup altogether. Reservation partitions (existing and the ones the partitions job creates) now vacuum after 10,000 + 1 % dead rows and always clean their indexes (`vacuum_index_cleanup=on`, faster cost limits). Recommended PostgreSQL autovacuum settings are in [operations](docs/operations.md#postgresql-settings-for-hot-rows-and-group-commit). Measured on the 2 M-attempt load-test database (one replica, unvacuumed after four 1,000/s runs): 280 k → 7.7 k dead rows, the admission limits statement 0.38–0.48 → 0.14–0.15 ms, saturation 989 → 1,032 ok/s (+4.3 %) and 952 → 996 ok/s at 1,000/s offered afterwards.

**rand 0.10** (supersedes Dependabot PR #14). Secrets (inference key secrets, sign-in state/nonce/PKCE verifier/browser binding, session and CSRF tokens, invitation tokens, file-store data keys, nonces and temp names) come from the OS CSPRNG through one fallible helper (`rand::rngs::SysRng`; `ThreadRng`, which panics when the OS source fails, is not compiled in). An OS RNG failure now fails closed instead of panicking: management `503` ("Secure random number generation unavailable", nothing created), sign-in `500` (no state or session stored), file store `unavailable` (nothing written), `bootstrap-dev` exits non-zero. The PKCE verifier no longer comes from the OIDC library's own generator. Routing's seeded weighted choice uses rand 0.10's `StdRng` (a request seed may now pick a different weighted candidate; seeds are per request and never stored). `aes-gcm`/`sha2` stay at 0.10.

## [0.3.2] - 2026-10-09

Fixes three gaps found in live DGX Spark acceptance. Routes whose connection profile can't serve the model (System One on `vllm`, rerank on `ollama`) are refused with 400 `route_unsupported_capability` at route creation, enabling, model setup and model protocol changes, using the one capability table the inference path uses; existing ones read "Not serving: <reason>". Pricing-v3 publications must state every meter the route's workload can use (priced, `not_applicable` or the new explicit `unknown`), else 400 `price_meters_incomplete`; budgeted admission on a price that cannot bound the hold now returns 503 `price_unbounded` (non-retryable) instead of a misleading `budget_exceeded`, and older prices stay unchanged. Both new management errors carry their machine code in `error.reason`, like every management error. Chat Completions accepts legacy `max_tokens` as an alias of `max_completion_tokens`. CI and the release pipeline no longer pull from Docker Hub (anonymous rate limits and an outage failed builds): the `Dockerfile`'s node and rust stages, PostgreSQL/Caddy test and staging-rehearsal images, BuildKit and the SBOM generator come from `mirror.gcr.io` (same digests), RustFS from `ghcr.io`, MinIO via the mirror with a retried pull, cargo-deny as a release binary, and the `Dockerfile` drops its `# syntax=` line; the runtime image and `deploy/staging/compose.yaml`'s defaults are unchanged (`STAGING_POSTGRES_IMAGE`/`STAGING_CADDY_IMAGE` override them). No migrations. Also five dashboard fixes (batch outcome labels, rounded batch cost hint, sub-cent trailing zeros, Explore title casing, truncated user emails) and reviewed Dependabot updates (minor/patch groups; base64 0.23, tower-http 0.7, webpki-roots 1.0). Notes: [`docs/releases/v0.3.2.md`](docs/releases/v0.3.2.md).

## [0.3.1] - 2026-10-09

Distroless runtime image (`gcr.io/distroless/cc-debian12`, pinned by digest; no shell, curl or package manager), the binary as entrypoint with the former shell entrypoint's `_FILE` secret import ported to Rust, and `open-model-gateway healthcheck` for the image `HEALTHCHECK`. Supply-chain scanning: cargo-deny (`deny.toml`), an npm production audit gate, CodeQL for JavaScript/TypeScript and Rust, and weekly grouped Dependabot updates; the Bedrock SDK drops its legacy hyper 0.14/rustls 0.21 connector. Rerank on the `openai_compatible`, `vllm` and `sglang` local profiles and System One on `openai_compatible` and `ollama`, with Add model offering those types only where the profile serves them. Fixes from the v0.3.0 screenshot pass: cooling-down routes answer a retryable 503 with `Retry-After` instead of 404, rounded money display with exact tooltips, aligned stat-tile charts, "Unpriced" unit-priced models, audit labels for every event, "No access" users, per-owner personal workspace rows, Logs that fit at 1440, consistent storage units, and clearer batch waits and lower-bound batch costs. No migrations. Notes: [`docs/releases/v0.3.1.md`](docs/releases/v0.3.1.md).

## [0.3.0] - 2026-10-09

Encrypted file store, gateway-owned Files API, batches for any model with capacity-aware scheduling for self-hosted servers, a "Jobs at once" limit, the video provider retired, and the first signed multi-arch release images. Migrations `0018` to `0022`. Notes: [`docs/releases/v0.3.0.md`](docs/releases/v0.3.0.md).

## [0.2.0] - 2026-10-09

Alerts, key safety, model compare, SCIM, JWKS refresh, metrics and backup tooling, async video and batch jobs, realtime audio, and constant-time budget admission. Migrations `0011` and `0013` to `0017`. Notes: [`docs/releases/v0.2.0.md`](docs/releases/v0.2.0.md).

## [0.1.0] - 2026-10-08

The single-enterprise rebuild: Team, Project and personal workspaces, OIDC platform roles, catalogs, multimodal workloads across five provider families, immutable micro-USD accounting, logs and Admin settings. Migrations `0001` to `0010`. Notes: [`docs/releases/v0.1.0.md`](docs/releases/v0.1.0.md).
